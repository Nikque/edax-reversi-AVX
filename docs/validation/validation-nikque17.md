## 2. 原因と証拠（原因確定報告で確定済みのもの）

ゼロから推測し直さず、原因確定報告・因果比較.json・strict-*.patch・Q対照を前提にしました。

| 原因 | 証拠 | 今回の扱い |
|---|---|---|
| 1. S3の1スレッド差は、bookの同点候補を選ぶ乱数の種が時計（`real_clock()`）であること | S3のseed固定2回は一致、seed変更で新旧とも同じ85局面が変わる、book offなら差0 | `book-seed` を追加 |
| 2. 並列展開は、他のworkerが反映したbookを `position_link` で読んでから探索する（完了順で探索入力が変わる） | Q対照（全探索1スレッド、seed固定）で並列2回が旧18局面差、直列は新旧4回一致、探索前のLink数の分岐を記録 | `book-reproducible` の番号順反映 |
| 3. 保存日時8バイト（オフセット10〜17） | 両版の保存仕様 | 変えない（比較で除外） |
| 4. base uniqueの1本差は旧版の改行なし最終行の読み落とし | 末尾改行の対照 | 修正済みの既存変更。今回は触らない |
| 保存順の差（並列反映の順がbucket内の順になる） | 新版並列2回：レコードは全一致、順だけ違う | 番号順反映で順も揃う。全件ソートは足さない |

ソースを読んで追加で確認したこと（実験では未確認）：
- 並列学習（`book-store-tasks` 2以上）は、レーンごとに乱数を `book->random` から種付けし、どのレーンがどの棋譜を打つかは終わる順で決まる。種を固定しても、棋譜ごとの乱数の列が実行ごとに変わり得る。
- 対象1件の周や、メモリ不足のときの1つずつの展開は、主探索（全スレッド）を使う。複数スレッドの探索は実行ごとに結果が変わり得る（原因確定報告のQで `CODEX_INNER_ONE` が必要だった理由）。
- `book correct` の並列workerは局面ごとにハッシュを消去しない。正確な評価値は同じだが、同じ評価値の手のどれを選ぶかが前の探索に依存し得る。

## 3. 修正の内容

### 既存仕様として残すもの（既定の動作は変えない）
- 既定の乱数の種は時計のまま（`book-seed = auto`）。
- 既定（`book-reproducible = off`）の並列展開：処理の内容はそのまま。共通部分を `book_expand_take`・`book_expand_search`・`book_expand_apply` に切り出しただけ。
- 保存日時は書き換えない。保存は全件ソートしない。hash lock修正、Cassio EOF、MSVC x86 AVX2、Androidヘッダーの修正には触れていない。
- 対局の探索（`play`・`go`）と時間制限つきの探索。

### 追加した設定（新機能）
- `book-seed <n|auto>`：book_init・book_load・book_import の3か所の種を、設定があればその値にする。
- `book-reproducible <on|off>`（既定off）。onのとき：
  1. 展開の探索は並列のまま、bookへの反映を todo の番号順にする（`book_expand_worker_ordered`）。反映の直前に、子局面のLinkを今のbookで確かめ直し（`position_links_current`）、違えばその1件だけ探索し直す。先に反映できるのは番号順の先頭だけなので、探索し直している間にほかの反映が割り込むことはない。各workerは、反映待ちが `64 × worker数` 件を超えると待つ。
  2. book関数の探索をすべて1スレッドにする：展開のpool、主探索の代わりの1スレッド探索（`book_search`）、planの初期スレッド数とスレッド追加、学習レーンのスレッド数とスレッド追加。
  3. 1スレッド探索のハッシュ表は、1スレッド実行の主探索と同じ大きさ（auto=21bit、上限21bit）。これで展開系のコマンドは 
-tasks 1` と同じbookになる。
  4. `book correct` の並列workerは、局面ごとにハッシュを消去する。

### 既定でも変わるもの
- 並列学習の乱数：レーンごとの種から、棋譜ごとの種（`book->random` から棋譜の番号順に引く）に変えた。既定では種が時計なので、選ばれ方のでたらめさは変わらない。ただし、学習後の `book->random` の状態は変わる（引く回数がレーン数から棋譜数になるため）。

### 文書の修正
- manual 7.6の「同時に広げている局面どうしは、互いを見ません」は不正確だった（先に反映されたものは見る）。実際の動作に合わせて直し、新しい設定の節を足した（日本語・英語）。設定表とconfig.iniにも2項目を追加した。manualの元原稿（作業PCの別のフォルダー）には反映していない。

## 4. 回帰テスト

`tests/regression.c` に `reproducible` を追加（`tests/README.md` に説明あり）。
- `book-seed`：数を指定すると book の乱数がその種で始まること、`auto`・負の数・数でない値では時計に戻ること。
- Linkの確かめ直し：子が増えたとき・子の評価値が変わったときに「古い」と判定し、張り直すと「最新」になること。
- 4スレッドで2回と1スレッドで1回、日時以外の保存内容が同じになること（`book new 2 52`、`book deviate 2 4`）。

実行の状況：
- 1回目（条件 `book new 2 36`、`deviate 4 8`）は、テスト側の想定の誤り（初期局面の4手が対称でLinkが4本になる）で失敗した。
- 想定を直した2回目は、`book-seed` とLinkの確かめ直しの2項目は通った。しかし条件が大きすぎ、bookが増え続けた（途中経過ファイル約197MB、ドライブの空き2.5GB）ので、止めた。途中経過ファイルはごみ箱へ移した。
- 条件を小さくした3回目（`book new 2 52`、`deviate 2 4`、1論理CPU、97秒）は**通った**。4スレッド2回と1スレッドで225局面のbookが日時以外一致。ただし、探索し直しの経路は0回で、この条件では通らなかった。
- そこで `expandredo` を追加した。2つの展開を逆の順で探索させ、必ず探索し直しが起きる形にしたもの。**通った**：後ろの展開は前の展開の反映を待ち、Linkが0本から1本に変わったので探索し直され、3局面とも `position_expand` を順に呼んだbookとLeaf・評価値・Linkまで一致した。古いLinkのままなら、Linkの評価値は −24 になり、正しい −30 と違っていた（このテストは探索し直しの抜けを見分けられる）。
