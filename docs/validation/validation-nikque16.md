## 手順・入力の範囲と残る制限

- 中盤は従来のmid.obfの30局面。学習は従来のreal30.txtの30本と、従来の約27万局面の小さいbook（book7.dat、11,908,840bytes、level18）を初期値としてbook learnを行った。29GBのbookは開いていない。n-tasks以外の設定は両版で同じ。
- base uniqueは従来のlines.txtの51,106非空行。今回10万局以上の既存入力は用意できなかったため、水増ししなかった。出力件数は実ファイルの行数で確認した。
- base uniqueの入力末尾には改行がない。出力out/unique.txtはAが51,105行、Bが51,106行で、A全体はBの末尾1行を除いたものと一致した。Bだけの1棋譜は入力の最終行と一致する。新旧で出力が違ったファイルとして記録する。これは最終棋譜の読込みを直した既存の変更と整合し、単なる順序差ではない。旧版だけに`WARNING: Cannot open file out/unique.txt`があるが、出力ファイルは両版で作られている。追加検証の全8実行の件数・SHAはテキスト出力の追加検証.json。
- PGОビルドは新旧とも終了0。学習中の`WARNING: Unknown command/Illegal move: "eof "`は新旧にあり、ログに残した。これをコンパイラ警告や異常終了とは数えていない。
- 再現用コマンド、cwd、終了コード、バイナリーSHA、ファイルSHAは各run.json。stdinは実ファイルのcommands.txt。親の試験ドライバーと元入力の保存場所は入力資料.jsonに記録した。

## 判断・推測（実測と区別）

上の一致・差分・秒数・終了コード・WSは実測またはファイル比較の結果である。数%程度の差だけで性能の変化を断定しない。複数スレッドの探索・学習の揺れ、バックグラウンド負荷、4組だけの標本数があるため、比とSD・再測定を合わせて判断する。日時だけのバイト差を、探索の結果が変わった証拠とは扱わない。

S3はbookを使うまま棋譜を学習し、S3offはbook offを入れる。ソースではbookの同点候補から乱数で手を選ぶ処理と、時刻による乱数初期化がある。この乱数選択はS3の1スレッドの揺れの原因候補だが、乱数を固定して切り分けた試験はしていないため、原因とは断定しない。32スレッドの新旧差が旧旧の1組を超えた結果も、同じ分布から4組を比べると最大値が大きくなり得るため、これだけで修正版固有の回帰を証明したとはしない。要求された観測範囲の条件が満たせなかった事実は表に残す。
