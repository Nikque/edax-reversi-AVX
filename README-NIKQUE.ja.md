# Edax 4.5.5 修正版

[English](README-NIKQUE.en.md) · [Releases](https://github.com/Nikque/edax-reversi-AVX/releases) · [修正一覧](RELEASE-NOTES.ja.md) · [ユーザーマニュアル](manual/ja/README.md)

この公開forkは上流の `v4.5.5`（`4cde6ff588f0eade07fcba0c7f02d5cd0cacd4ee`）を基点としています。修正後のソース、再ビルドしたWindows・Linux・macOS・Android用実行ファイル、元のGPL-3.0 [ライセンス](LICENSE)を公開しています。上流の `master` ブランチは残し、修正版の `edax-4.5.5-fixes` を既定ブランチに設定しました。

**このブランチ（`eval2`）は、評価関数を変えた別の系列です（この版は v4.5.5-eval2.2）。** 既定のブランチ `edax-4.5.5-fixes`（v4.5.5-nikque.13）との違いは、下の「v4.5.5-eval2.1 の変更点」に書いた評価関数の変更だけです。

## v4.5.5-eval2.2 の変更点

v4.5.5-eval2.1（v4.5.5-nikque.9 のソースに評価関数の変更を足したもの）に、**v4.5.5-nikque.10〜13 の変更を全部取り込みました。** 評価関数と `eval.dat` は v4.5.5-eval2.1 のままで（`eval.dat` は同じファイルです。SHA-256 `1870f8fa5eecb6df972a4d83224832f9a620745cdc67c2d9b17bcd0ba09ea172`）、この系列だけの新しい変更はありません。

- **取り込んだもの**：下の「v4.5.5-nikque.13 の変更点」「v4.5.5-nikque.12 の変更点」「v4.5.5-nikque.11 の変更点」「v4.5.5-nikque.10 の変更点」に書いてあるもの全部です（bookの不具合の修正、`book leaf-recalculate`、`book subtree`・`book prune` を速くする変更、`book-expand-tasks = auto` の変更、libedaxの関数の追加など）。ソースの違いは、v4.5.5-nikque.13 に対して、v4.5.5-eval2.1 と同じ4ファイル・約40行（`src/const.h`・`src/eval.c`・`src/eval.h`・`src/midgame.c`）だけです。
- **探索の結果は v4.5.5-eval2.1 と同じです**：1スレッドの `-solve`（問題集69局面：完全読み39、level 18 の中盤30）で、深さ・評価値・ノード数・読み筋が、v4.5.5-eval2.1 の配布版と一致しました（この版のソースの試験用ビルドで確認）。上流の `eval.dat` を使ったときは、v4.5.5-nikque.13 と同じ結果・同じノード数です（同じ69局面）。
- **`eval.dat` を替えた後のbookの評価値を計算し直すには**、`book leaf-recalculate` 系の命令（v4.5.5-nikque.12 で足したもの）が使えます。小さいbook（level 10、1,563局面）で試すと、上流の `eval.dat` で求めたLeaf 1,437個を、この系列の `eval.dat` で計算し直して、915個の評価値が変わりました（最大 +4／−5、手が変わったのは273個）。同じ `eval.dat` でもう一度行うと変化は0で、上流の `eval.dat` に戻して行うと元のbookに戻りました（1スレッドの探索8個）。完全読みの局面は対象外です（v4.5.5-nikque.12 の説明のとおり）。大きなbookでの時間は、この系列では測っていません。
- **bookの命令の速さとメモリ**（公開の後、2026-10-08 に追記。v4.5.5-eval2.1 と、この版の配布用の `wEdax-x86-64-v4.exe` どうし。どちらもこの系列の `eval.dat`。Ryzen 9 9950X）：6億6162万局面のbook（level 18）を読んで `book deviate2 5 5` を32スレッドで動かすと、局面の選択の後の5分間に広げた数は、v4.5.5-eval2.1 が 11,673・11,592、この版が 13,240・13,188 でした（2回ずつ）。局面の選択は 32.0秒 → 30.6〜30.7秒、最大メモリは 33,410〜33,412MB で同じです。649万局面のbookの `book deviate2 3 6` の1周（3回ずつ）は、1スレッドの探索8個の設定で両方とも 25.9秒、32スレッド・`book-expand-tasks = auto` では 13.0秒 → 11.1〜11.2秒でした。空のbookから `book deviate` を120周（4回の中央値）は、1スレッドで 29.14秒 → 29.13秒、8スレッドで 22.28秒 → 22.18秒、最大メモリは同じです。v4.5.5-eval2.1 は v4.5.5-nikque.9 まで、この版は v4.5.5-nikque.13 までの変更を含みます。32スレッドでの差は、v4.5.5-nikque.10 で変えた `book-expand-tasks = auto` の決め方（対象の多い周は、1スレッドの探索をスレッドの数だけ動かす）によるものと考えています：649万局面のbookの1周を `book-expand-tasks 16`（v4.5.5-nikque.9 までの `auto` と同じ、2スレッドの探索を16個）にして3回ずつ測ると、v4.5.5-eval2.1 は3回とも `auto` と同じ時間（13.0〜14.0秒）で、この版は 12.5〜15.5秒（`auto` は 10.7〜12.1秒）でした。実bookでは、この切り分けは測っていません。

## v4.5.5-eval2.1 の変更点（評価関数の新しい系列）

**これは、評価関数（`eval.dat`）を変えた別の系列です。** v4.5.5-nikque.9 のソースに、評価関数の変更だけを足しました。ブランチ `eval2` から公開しています。既定のブランチ（`edax-4.5.5-fixes`）と最新のReleaseは、v4.5.5-nikque.9 のままです。評価値と探索の結果が変わるので、これまでと同じ評価値が必要なときは、v4.5.5-nikque.9 を使ってください。

- **評価関数**：これまでの46個のパターンはそのままで、**両者の着手可能数（打てる場所の数）** を足しました。重みは、上流（v4.5.5）の重みを出発点にして、全部を学習し直しました。
- **強さ**：上流の `eval.dat` との対局（同じ実行ファイル、同じlevel、1スレッド）で、level 6・10・18・21 のどれも **+17〜22 Elo** でした。
- **速さ**：level 18〜24 の探索は、v4.5.5-nikque.9 の配布版より **2〜15% 短い時間**で終わります（AVX2版・AVX-512版、1〜32スレッド。読む局面の数が 8〜20% 減るため）。
- **遅くなる条件があります**：level 10 など浅い探索（AVX2・AVX-512版で約5%、標準の64ビット版で13%、32ビット版で20〜24%）、完全読み（3〜6%）、32ビット版の level 18（4〜7%）。下の「遅くなる条件（まとめ）」に全部書きました。
- bookのファイル形式、設定、コマンド、libedaxのAPI、最大メモリは、v4.5.5-nikque.9 と同じです。

### 評価関数の変更

- 評価値に、「手番側の着手可能数」と「相手側の着手可能数」のそれぞれに対応する重みを足します。重みは、手数（60 − 空きマスの数）ごとに、着手可能数 0〜31 の表（32以上は31として扱います）を2つ持ちます。パターンの重みと同じ単位（1石＝128）です。
- `eval.dat`（版 3.3.0）：これまでの内容（46パターンの重み、手数61個分）の後ろに、`MOBW` の4文字と、61×64個の16ビットの値を足した形式です。大きさは 13,952,436 バイトから 13,960,248 バイトになりました。SHA-256 は `1870f8fa5eecb6df972a4d83224832f9a620745cdc67c2d9b17bcd0ba09ea172` です。
- ソースの変更は、`src/const.h`・`src/eval.c`・`src/eval.h`・`src/midgame.c` の約40行です。`eval.dat` に表があれば読み、評価関数を呼ぶ2か所（`search_eval_0`・`search_eval_1`）で、着手可能数を数えて表の値を足します。表がなければ何も足しません。
- 特徴の数（46）と、探索の中で特徴を更新する処理は変えていません。

### 遅くなる条件（まとめ）

v4.5.5-nikque.9 の配布版（上流の `eval.dat`）より、この版（新しい `eval.dat`）が遅い条件です。

| 条件 | 時間 |
|---|---|
| level 10（浅い探索）、AVX-512版・AVX2版 | 4.5〜5.5% 長い |
| level 10、標準の64ビット版（`wEdax-x86-64.exe`） | 13.5% 長い |
| level 10、32ビット版 | 20〜24% 長い |
| level 18、32ビット版 | 4〜7% 長い |

| 完全読み、32スレッド | 約6% 長い（ノード数 +9%） |

- bookの学習（`book learn`・`book deviate`・`book fix` など）の時間は測っていません。中身は同じlevelの探索の繰り返しなので、上の表のlevelごとの比に近いはずですが、level 18 のbookでも、終盤の局面の探索（完全読み）の部分は遅くなります。

### 正確さ

- level 18 の評価値を、完全読みの結果（石差）と比べました（空きマスの数が違う12の集まり、2850局面、1スレッド）。平均の誤差は、上流の `eval.dat` で 1.089石、新しい `eval.dat` で 1.067石、二乗平均の誤差は 2.02石 と 1.94石です。読む局面の数は減りましたが、評価値は少し正確になりました。
- 探索の枝刈り（ProbCut）の設定は変えていません。新しい重みで、浅い探索と深い探索の差を測り直しました（1200局面、深さ0〜16）。空き32以上では上流の重みの 0.93〜1.00倍、空き24〜31 で深さ12〜16 のところは 1.18〜1.24倍でした。誤差の見積もりを 1.1倍・1.2倍にする試験もしましたが、正確さの得（平均の誤差 1.01石・0.97石）より、遅くなる分（level 18 の時間が 1.16倍・1.47倍）のほうが大きかったので、採用しませんでした（この段落の2つの試験は、今の重みに決める前の、上流の重みへの引き寄せを弱くした重みで行ったものです）。

### 重みの作り方と学習データ

- 46個のパターンと着手可能数の表を、同時に学習しました（手数2〜53）。上流の重みから離れすぎないように、上流の重みとの差に罰を付けています。対称な形のパターンは、重みを共有しています。
- 学習データ（局面と、その正解の値）：

### 新しい設定：book-leaf-recalculate-rounds（Leafの再計算を繰り返す）

`book leaf-recalculate`（と `2`・`3`・`4`）は、1回たどって終わる命令です。ところが、Leafを計算し直すと評価値が動き、命令がたどる範囲も動くので、**同じ命令をもう一度行うと、1回目には範囲の外だったLeafが新しく対象になります**。649万局面のbookで `book leaf-recalculate4 1 1` を繰り返すと、対象は 4,066 → 780 → 247 → 485 → 386、評価値が変わった数は 1,419 → 411 → 42 → 46 → 0 でした。v4.5.5-nikque.12 の説明の「同じ命令を続けてもう一度行うと、評価値も手も変わりませんでした」は、bookの全部を範囲にした場合の話でした（訂正しました）。

`book-leaf-recalculate-rounds = n`（`config.ini`、コマンドラインの `-book-leaf-recalculate-rounds n`、libedaxの `edax_set_option`）で、命令は「たどる → 計算し直す → negamax」を最大 n 回繰り返します。**Leafが1つも変わらなかった回で終わります。** 既定は 1 で、v4.5.5-nikque.12 と同じ動作・同じ表示です。

- 上のbookで `book-leaf-recalculate-rounds = 10` にすると、5回で終わり（`5964 leaves, 1918 scores changed …, 5 rounds`）、同じ命令を6回入力したbookと同じになりました（1スレッドの探索8個、61秒）。
- 複数スレッドの探索（対象の少ない回など）は実行ごとに値が少し変わるので、「変わらなかった回」が来ないことがあります。そのときは n 回で終わります。
- 表示：各回の前に `Book leaf-recalculate4 1 1: round 2/10`、最後の行の末尾に行った回数（`, 5 rounds`）。数は全部の回の合計です。
- 保存は、これまでどおり、最後に1回と、`book-save-interval` ごとの途中の保存です。
- 小さいbook・狭い範囲での回数で、大きなbookで何回かかるかの見込みではありません。

`leaf-recalculate`・`leaf-recalculate3` で、1回目のたどりの一覧がメモリ不足で作れなかったときにも、警告を表示するようにしました（これまでは2回目の一覧しか見ていませんでした）。

### 直していないもの・知っておくこと

- **作ったばかりのLeafでも、計算し直すと値が変わることがあります**（v4.5.5-nikque.12 の説明の「0.1%」と「1.6%」）。何によって変わるのかを調べました（649万局面のbook、level 18、8手進めた局面からの `book deviate2 3 6` の1周、1スレッド：足した 1,311局面と、展開した 1,315局面のLeafを、1つずつ計算し直して比べました）。
  - 足した局面：bookは、局面を「8通りの対称のうちの決まった1つの向き」で持ちます。新しく足す局面は、親の局面に手を打ったときの向きのまま探索され、後から計算し直すときは、bookの向きで探索されます。計算し直して評価値が変わったのは 1,311局面のうち2局面（0.15%。どちらも1の差）で、足す局面をbookの向きに直してから探索する変更を試すと、0局面になりました。探索する盤面の向きで結果が変わる理由は、確かめていません（手を調べる順番が変わるためと考えています）。
  - 展開した局面：次のLeafを、足した局面の探索の内容がハッシュ表に残ったまま求めます。計算し直して評価値が変わったのは 1,315局面のうち19局面（1.44%。1か2の差）で、同じ変更を試すと、2局面になりました。
  - **この変更は、この版には入れていません。** 合わせて 2,626個のうち21個が2個に減りますが、`book deviate` 系の探索のノード数が 0.35〜0.46% 増えたためです（649万局面のbookの2つの周。時間は測っていません。足した局面を別の向きで探索すると、その探索の内容を、展開した局面の探索が使えなくなるためと考えています）。どちらの値も、同じlevelの探索の結果です。
- **`book deepen` は、局面のlevelを上げません**（上流から）：局面のlevelがbookのlevelと違う局面のLeafを探索し直す命令ですが、探索は「その局面の今のlevel」で行い、levelも書き換えません。説明文（bookのlevelに合わせて評価し直す）のとおりには働きません。この版で直したのは、合法手のない局面のLeafを消す点だけです。
- **初期局面からたどれない局面は、negamax されません**：negamax は初期局面からLinkをたどるので、どの局面からもLinkが張られていない局面は、評価値が更新されません。古い版（v4.5.5-nikque.2 までと上流）の `book merge` で入った局面は、評価値が入らないまま（−127）のことがあります。`book deviate` 系・negamax・切り詰めは、これらの局面を使いません。後から親のLinkが張られれば、次の negamax で評価値が入ります。初期局面で `book subtree` を行うと、たどれない局面は消えます。
- `book fix` が局面を直すときは、その局面のlevelをbookのlevelにして、そのlevelで探索します（上流の作り）。levelの低いbookを取り込んで直すと、時間がかかります。
- bookの手を使う対局（`book learn` の打ち継ぎなど）は、評価値の同じ手を乱数で選び、乱数の種は時計です（上流から）。1スレッドでも、実行ごとにbookが変わることがあります。
- **途中の局面から始まる対局は、`.txt` と `.sgf` では読み戻せません**（上流から）：保存は最初の局面を書きますが（`.txt` は `盤 手番;手順`、`.sgf` は `AB[…]AW[…]PL[…]`）、読み込みは、どちらも通常の初期局面からの手順として読みます。`.sgf` は読み込まれず（警告を表示。盤は前のまま）、`.txt` は、警告を表示して、手のない対局になります。途中の局面から始まる対局は、`.ggf`・`.pgn`・`.edx` で保存してください。
- **Windowsでは、`book-file` のフルパス（フォルダーを含めた長さ）を240文字以内にしてください**：bookの保存は、いったん「保存する名前＋`.tmp.`＋プロセスの番号」という一時ファイルに書いてから名前を替えます（このforkで足した仕組みで、全部を書き終えるまで元のファイルを置き換えません）。`book store` の `.store` や `book deviate2` の `.dev2` のように、`book-file` に拡張子を足した名前への保存では、その分も長くなります。一時ファイルのフルパスがWindowsで使える長さ（259文字）を超えると、`Cannot open temporary book …` と表示して、その保存だけが行われません（メモリの中のbookはそのままで、処理は続きます）。203文字のbook名で試すと、一時ファイルのフルパスが259文字なら保存され、260文字だと `.store` だけが保存されませんでした（v4.5.5-nikque.12 でも同じ動きです）。240文字以内なら、どの保存も収まります（足す拡張子は最大6文字、`.tmp.` が5文字、プロセスの番号が8桁までとして）。Linuxでは確かめていません。

## v4.5.5-nikque.12 の変更点

新しい命令 `book leaf-recalculate`（Leafの再計算）を足し、`book subtree`・`book prune` をさらに速くしました。`book` の後ろの語は、大文字でも通るようになりました。評価データ `eval.dat`、bookのファイル形式、探索のコードは変わりません。これまでの命令でできるbookが変わるのは1か所です（`book subtree` の後のLinkの張り直しをやめた。下の「動作が変わるところ」）。

### 新しい命令：book leaf-recalculate（Leafの評価値を計算し直す）

`book deviate`・`book deviate2` がたどる範囲の局面について、Leaf（まだLinkになっていない手のうちの最善手と、その評価値）を探索し直す命令です。`eval.dat` を新しいものに替えた後で、bookの中の古い評価値を新しい評価関数の値に置き換えるためのものです。局面は足しません。

| 命令 | たどり方 | 計算し直すLeaf |
|---|---|---|
| `book leaf-recalculate X Y` | `book deviate X Y` と同じ | `book deviate X Y` が「展開する」と選ぶ局面のLeaf |
| `book leaf-recalculate2 X Y` | `book deviate2 X Y` と同じ | `book deviate2 X Y` が「展開する」と選ぶ局面のLeaf |
| `book leaf-recalculate3 X Y` | `book deviate X Y` と同じ | たどった局面の全部のLeaf（Leafが範囲の外の局面も） |
| `book leaf-recalculate4 X Y` | `book deviate2 X Y` と同じ | たどった局面の全部のLeaf（Leafが範囲の外の局面も） |

- X・Y の意味・既定値・範囲は、対応する `book deviate`・`book deviate2` と同じです。今の盤面から始めること、`book depth` の範囲だけをたどることも同じです。
- **1回たどって終わります**（`book deviate` のような繰り返しはしません）。流れは「今の盤面から negamax → 選択 → 選んだLeafを探索し直す → negamax → 保存」です。`book leaf-recalculate`・`3` は、`book deviate` の1周と同じく選択を2回行います（手番の側が X 以内の手を選ぶ場合と、相手の側が選ぶ場合。2回目は、1回目のLeafを計算し直した後のbookで選び、まだ計算し直していないLeafだけを対象にします）。
- **完全読みの局面のLeafは、どの命令でも計算し直しません**（level 18 では空き21以下。評価関数によらず同じ値のため）。全部の手がLinkになっていて、Leafのない局面も対象外です。（**v4.5.5-nikque.13 から**、パスの局面のLeaf（手が「パス」のLeaf）も計算し直します。v4.5.5-nikque.12 では対象になっていませんでした。）
- `3`・`4` は、たどった局面のLinkの先にある「bookの深さより1つ深い局面」（LinkがなくLeafだけを持つ、いちばん深い層）のLeafも計算し直します。`book leaf-recalculate`・`2` は、`book deviate`・`book deviate2` と同じく、その層は対象にしません。
- 探索は、その局面に記録されている level で行います。**探索ごとにハッシュ表を空にしてから始めます。** 同時に行う探索の数・スレッド・ハッシュ表の大きさは、`book deviate` の展開と同じです（`book-expand-tasks`）。1スレッドの探索で行われる場合（`book-expand-tasks = auto` で、level 18 以下、対象が `n-tasks` の32倍以上あるとき）は、同じbookに同じ命令を行えば、スレッドの数や順番によらず同じ結果になります。
- 途中の保存：`book-save-interval` 分ごとに、`book.dat.leaf`・`.leaf2`・`.leaf3`・`.leaf4`（命令ごと）に保存します。終わりにも同じファイルに保存します。途中の保存は「一部のLeafだけ新しく、negamax はまだ」の状態なので、読み込んで使うときは `book negamax` を行ってください。続きから再開する仕組みはありません（もう一度実行すると、最初から計算し直します）。
- たどらなかった局面のLeafは、そのままです。今の盤面が初期局面でないとき、今の盤面から届かない局面のLinkの評価値は、`book negamax` を行うまで古いままです（`book deviate` と同じ）。

### book-expand-tasks = auto：展開の対象が多い周は、1スレッドの探索をスレッドの数だけ

同梱の `config.ini` の `book-expand-tasks = auto` は、level 18 以下では、2スレッドの探索を `n-tasks / 2` 個同時に動かしていました。この版では、level 18 以下で、その周の展開の対象が **`n-tasks` の32倍以上**（32スレッドなら1,024件以上）のとき、1スレッドの探索を `n-tasks` 個動かします。それより対象の少ない周、level 19 以上、`book-expand-tasks` を数で指定した場合は、v4.5.5-nikque.9 と同じです。1スレッドの探索のハッシュ表は、棋譜の学習の1スレッドの探索と同じ大きさ（level 18 以下は19ビット＝14MB）です。

| 32 | 8,270、8,086 | 10,247、10,195（約1.25倍） | 1,432MB → 1,001MB |
| 8 | 2,628 | 3,988（1.52倍） | 663MB → 556MB |

**実book（6億6162万局面）の `book deviate2 5 5`（1周の対象 2,753,399件）では、差は小さくなります。** 展開する局面の探索が重く（1件あたり約3,300万ノード）、2スレッドの探索でも無駄が少ないためです。同じ局面を同じ順に展開した最初の420秒で比べると、1件あたりのノード数は 3.49×10^7 → 3.26〜3.29×10^7（約6.5%少ない。この版は4回）、全スレッドを合わせた速さは同じ程度でした。時間で測った2組は、毎秒 35.1件 → 37.4件、34.2件 → 35.5件でしたが、同じビルドでも時間帯で毎秒32〜40件と揺れたので、**時間での得は「6〜7%の見込み」で、確かめられたのはノード数の差です。**

## v4.5.5-nikque.9 の変更点

v4.5.5-nikque.8 と edax_runner v5.3.0-nikque.2 の総点検で見つかった不具合を直し、棋譜の学習（`book learn`）を少し速くしました。新しい機能はありません（libedaxに関数を2つ、設定を1つ足しました）。評価データ `eval.dat`、bookのファイル形式、1スレッドの探索の結果とノード数は変わりません。動作が変わるところは、下の「動作が変わるところ」にまとめました。

### 複数スレッドの探索の修正

上流（v4.5.5）から続く並列探索の競合を2つ直しました。

- **止めたはずの探索が動き続ける・子スレッドが手を探索せずに終わる**ことがあり、手が探索されないまま「全部の手を探索した」として置換表に書かれるノードができていました。32スレッドの通常の探索で、終盤の完全読み 4,000局面で 1,294個、中盤 level 21 の 360局面で 8,453個（修正後はどちらも 0 個）。最終結果まで誤ることはまれです（修正前のコードでも、終盤の完全読み 28,000局面で 0 回）。
- **探索を止める要求が失われる**ことがありました（240万回の要求で3回）。v4.5.5-nikque.8 の「止めて、スレッドを足して続ける」処理（`book-store-tasks`）は、止めた探索の置換表でそのまま探索し直すので、この2つの影響を受けやすく、bookのLeafが最善でない手・評価値になり得ました（止める要求を乱発する試験で、修正前は 12,800局面で2回の誤り、修正後は 13,920局面で 0 回）。
- 1スレッドの探索は変わりません（結果とノード数が v4.5.5-nikque.6・v4.5.5-nikque.8 と一致）。複数スレッドの探索の速さは、PGOなしの同じ作り方のビルドどうしで、v4.5.5-nikque.8 に対する時間の比が 0.98〜1.01（終盤の完全読み・中盤 level 18〜24、1・2・8・32スレッドの9条件。標準誤差 0.003〜0.02）で、遅くなったと言える条件はありませんでした。bookの処理の速さとメモリは、下の「速さとメモリ（実測）」にあります。

### bookの不具合の修正

- **`book merge` を同じ実行の中で2回以上行うと失敗することがある**（v4.5.5-nikque.3 から）：rootから届かない局面（標準でない開始局面から `book store` した対局など）を含むbookを統合した後、次の `book merge` が「duplicated position」で失敗し、その失敗の取り消しで、前のmergeで入った局面までメモリ上のbookから消えていました。
- **壊れたbookで、複数スレッドの `book negamax` が異常終了する**（v4.5.5-nikque.3 から）：Linkが自分自身や上の局面に戻るbookで、スタックを使い切っていました。複数スレッドのnegamaxは「石が増える手」と「パス」のLinkだけをたどります（正しいbookのLinkはすべてこれに当たります）。
- **`book import` に失敗すると、今のbookが消える**（上流から。libedaxの `edax_book_import` も同じ）：開けないファイルを指定すると、bookが1局面の新しいbookに置き換わり、終了時にそれがbookファイルへ上書き保存されていました。開けない・局面が1つもないファイルでは、今のbookを保ちます。読めない行は飛ばして続けます（最初の10行は理由を表示）。
- **起動時に読めなかったbookファイルが、学習の後で上書きされる**：壊れている、または、ほかのプログラムが開いていて読めなかったbookファイルは、その名前へ保存するとき、先に `<名前>.damaged`（あれば `.damaged.1`…）に名前を変えて残します。ほかのプログラムが開いていて読めなかっただけのbookを「ファイルがない」ものとして扱うこともやめました。
- **`base complete`・`base correct` が、読み込めないファイルを削除する**（上流から。libedaxも同じ）：読み込めたときだけ削除・保存します。
- **`book new` に範囲外のlevel**（0〜60 の外）を指定すると、表の外を読み、戻ってこないことがありました。警告を出して今のbookを残します。
- **長すぎるbookファイル名**（`FILENAME_MAX - 8` 文字超。Windowsでは252文字超）で異常終了していました。警告を出して無視します（前の名前か既定の名前のまま）。
- **levelが60を超える局面を持つbook（壊れたファイル）**：`book info` が配列の外へ書いていました。`book fix` が作り直します。bookファイルのヘッダーのlevelは 0〜60 に丸めます（警告つき）。
- `book store` でLinkが増えただけのとき、終了時にbookファイルへ保存されませんでした。
- 同時に行う探索を使うと、探索ログ（`-search-log-file`）が途中で閉じていました。

### 学習（`book learn`、libedaxの `edax_book_store_games`）の修正

- **255バイトを超える行が切られる**（v4.5.5-nikque.7 から）：手の間に空白が多い行で、切れ目が手と手の間に来ると、短い手順が「学習した」ことになっていました。空白を除いてから読みます（128手以上の行は、棋譜ではないので学習しません）。
- **持ち時間つきの学習で、同時に行う対局が残り時間を減らさない**（v4.5.5-nikque.7 から）：毎手「残りは持ち時間の全部」として探索していました（1人10秒の対局8局で、52.1秒 → 19.5秒）。固定levelの学習は変わりません。
- **行の先頭の randomness（`<数>,<手順>`）の上限をなくしました**：これまでは 127 までで、128 以上の行は「棋譜ではない」として学習しませんでした。`book-randomness` の設定と同じく、どの数でも受け付けます（評価値の差は最大128なので、128以上はどれも「bookの手のどれでも」の意味です）。

### メモリ・スレッドが足りないとき

- **同時に行う探索の領域が確保できないと、プログラムが終了していました**（32ビット版で `-h 25` など）。保存していない学習は失われていました。確保できないときは、同時に行う探索を減らして（0個なら1つずつ）続けます。警告は `not enough memory to search the positions at the same time`、`not enough memory to play N games at the same time`。
- **スレッドが作れなかったとき**、探索やbookの処理が止まったまま進まなくなることがありました（上流の探索と、v4.5.5-nikque.3〜7 のbookの処理）。作れた数のスレッドで続けます（警告 `cannot create a thread: the search uses N threads instead of M`）。
- 32ビット版：同時に行う探索を作るときに、128MBの余裕を残します。8947万局面以上のbookを読むと、確保する大きさの計算があふれて領域の外に書いていました（エラーを出して今のbookを保ちます。32ビット版では、この大きさのbookは読めません）。

### 設定・コマンド

- `config.ini`・コマンドライン・実行中のコマンドで、**数値でない値・on/off でない値**（`level = abc`、`n-tasks = 4x` など）は、警告を出して無視します（これまでは、警告なしで無視、または途中まで採用）。
- 実行中に `n-tasks` を下げても、`book-store-tasks`・`book-expand-tasks` の数は保たれます（これまでは切り詰められ、`n-tasks` を戻しても戻りませんでした）。
- PATHから名前だけで起動して、作業フォルダに `config.ini` がないときは、警告を出します（既定値で動きます）。
- **コマンドをファイルから渡すとき（`edax < file`）、`quit` は順番どおりに実行します**（これまでは、`quit` の前のコマンドが実行されないまま終わることがありました）。端末とパイプは従来どおりです。
- Windows：強制終了で残った `book.dat.tmp.<番号>` を、次の保存のときに消します。
- xboard の `cores`・`memory`、NBoard の `depth` は、範囲に丸めます。
- Linux の `-cpu`：bookの処理のスレッドも、CPUごとに固定します（これまでは全部 CPU 0 に重なっていました）。`-cpu` を付けたときは、同時に行う探索（`book-store-tasks`・`book-expand-tasks`）を使いません。
- bookの読み込み・保存・統合のエラーの文の末尾に、改行を足しました。
- **新しい設定 `book-store-auto-save`**（`on`／`off`、既定は `on`＝これまでと同じ）：`off` にすると、`book store` と `book learn`（libedaxの `edax_book_store`・`edax_book_store_games`）の後の `<bookファイル>.store` への保存を行いません。学習のたびに自分でbookを保存するプログラム（edax_runner）では、book全体が2回書かれていたので、そのためのものです。学習の内容は変わりません。同梱の `config.ini` には書いていません（既定のまま）。

### libedax

- **追加した関数 `edax_book_save_checked`**：`edax_book_save` と同じ保存をして、保存できたら 1、できなかったら 0 を返します（`edax_book_save` は、元のlibedaxと同じく何も返しません。ほかのプログラムがbookファイルを開いている間などは、stderrにエラーが出るだけでした）。
- **追加した関数 `edax_book_failed`**：直前のbookの処理（`edax_book_store`・`edax_book_deviate`・`edax_book_add_board` など。どれも元のlibedaxと同じく何も返しません）が、メモリ不足で局面をbookに追加できなかったときに 1 を返します。bookの関数は始めにこの状態を消すので、確かめたい関数のすぐ後に呼びます。追加した関数は7個になり、エクスポートされる関数は100個（元のlibedaxと同じ93個＋追加7個）です。
- **`edax_book_store_games` の状態の文字に `'2'` を足しました**：`'1'`＝学習した、`'0'`＝学習しない（打てない手・棋譜ではない行）、`'2'`＝失敗（メモリ不足で局面をbookに追加できなかった。その行はまだ学習されていません）。

### 棋譜の学習を少し速く（終わった対局のスレッドを、残りの対局に回す）

`book learn`（libedaxの `edax_book_store_games`、edax_runner のまとめ学習）は、1組の棋譜を同時に対局させます（`book-store-tasks = auto` なら、1局につき1スレッド）。これまでは、早く終わった対局のスレッドは、いちばん長い対局が終わるまで何もせずに待っていました（32本の組で、最初の1秒で大半の対局が終わり、残りの2〜3秒は数本だけが動いていました）。この版では、**対局が残っていないスレッドを、まだ対局している探索に次の手から足します**（手と手の間で足すので、探索を止めることはありません）。

- 足すのは、1局あたりのスレッドが7以下のときだけです。8スレッド以上で対局している場合（棋譜の数が少ないとき）は、足しても速くならなかったので（下の表の注）、これまでとまったく同じ動作です。
- `book-store-tasks = 1` のときと、対局が1局だけのときも、これまでと同じ動作です。

## v4.5.5-nikque.8 の変更点

v4.5.5-nikque.7 で既定にした `book-store-tasks = auto` に、**探索の数が少ないときや、levelが高いときに、v4.5.5-nikque.6 より遅くなる問題**がありました。同時に行う探索へのスレッドの配り方を直しました。変更はこれだけです。評価データ `eval.dat`、bookのファイル形式、探索結果、`book-store-tasks = 1` のときの動作は変わりません。bookの内容が壊れる種類の問題ではありません（v4.5.5-nikque.7 で作ったbookは、そのまま使えます）。

### 問題

v4.5.5-nikque.7 は、棋譜の学習（`book store`・`book add`・`book learn`）と、Linkの張り直し（`book fix`・`book merge`・`book import` など）で必要になる探索を、「1スレッドの探索」として同時に行います。探索の数がスレッドの数より少ないときや、短い探索の中に長い探索が混じっているときは、いちばん長い探索が1スレッドのまま終わるまで、ほかのスレッドは何もせずに待っていました。levelが高いほど、長い探索（複数スレッドがよく効く探索）が増えるので、影響が大きくなります。level 18 で多くの棋譜を学習する場合には現れないため、公開前の計測では見つけられませんでした。

### 修正

- **探索の数がスレッドの数より少ないとき**：最初から `n-tasks ÷ 探索の数` スレッドずつ使います。
- **始める探索がなくなったとき**：まだ動いている探索をいったん止め、終わった探索のスレッドを足して続けます。ハッシュ表はそのまま使うので、止めるまでの探索は無駄になりません。使えるスレッドが2倍以上になるたびに行います。
- **探索が1つだけのとき**：`book-store-tasks = 1` とまったく同じ探索をします（追加のメモリも使いません）。
- **探索用の領域**（探索ごとのハッシュ表など）は、始める探索が残っている間だけ作ります。短い探索が少しあるだけのときに、スレッドの数だけ作ることがなくなりました。

### 棋譜の学習を複数のスレッドで：book-store-tasks（新しい設定）

（v4.5.5-nikque.8 で、同時に行う探索へのスレッドの配り方を直しました。この節の時間と「いちばん長い探索が終わるまで待つ」という説明は、v4.5.5-nikque.7 のものです。上の「v4.5.5-nikque.8 の変更点」を参照してください。）

`book store`（対局した棋譜をbookに入れる）と `book add`（棋譜のファイルをbookに入れる）は、棋譜の局面を終局側から1つずつ探索してbookに加えます。1回の探索は短い（level 18 で0.1秒ほど）ので、探索のスレッドを増やしても8スレッドあたりで頭打ちになり、多くのCPUを使いきれませんでした。このため、Edaxやedax_runnerを何本も同時に起動し、後でbookをmergeする使い方が行われていました。新しい設定 `book-store-tasks` で、1つのEdaxが多くのスレッドを使って学習します。

| `book-store-tasks` | 動作 |
|---|---|
| `auto`（既定。同梱の `config.ini` も、`config.ini` がない場合も） | `n-tasks` 本の棋譜を同時に学習します（1本につき1スレッド）。 |
| 数値 n（2以上） | n 本の棋譜を同時に学習します（1本につき `n-tasks / n` スレッド）。 |
| `1` | v4.5.5-nikque.6 までと同じ。局面を1つずつ、`n-tasks` の全スレッドで探索します。できるbookも v4.5.5-nikque.6 と同じです。 |

`n-tasks` が1のときは、`auto` も `1` と同じです。`book-store-tasks` が1以外のときの動作：

1. **先に調べる**：棋譜の局面のうち、bookに加える局面と、その局面の探索から除く手（すでにLinkになっている手）を、bookを変えずに調べます。これは、bookにある局面と、棋譜が加える局面だけで決まります。
2. **同時に探索する**：調べた探索を全部、1スレッドの探索として同時に行います（同時に動かす数は `n-tasks` まで）。それぞれの探索は自分のハッシュ表を持ち、空の状態から始めます。
3. **従来と同じ順序でbookに加える**：局面を加える順序も、Linkの付け方も、従来と同じです。探索の結果だけ、2 のものを使います（先に調べていなかった探索が必要になったら、その場で従来どおり探索します）。

新しいコマンド `book learn <ファイル>` は、ファイルの各行の棋譜について「その手順を打つ → 終局までEdaxどうしで対局する → `book store`」を行います（プロンプトの `init`・`play <手順>`・終局まで `go`・`book store` と同じで、edax_runnerの学習リストの「Edax対Edax」の行と同じ書き方です）。1行に1局で、`f5d6c3` のような手順、または `2,f5d6c3` のように `book-randomness` の値と手順を書きます。空行、`#` で始まる行、`//` を含む行は読み飛ばします。

- `book-store-tasks = 1` では、1行ずつ、上のコマンドとまったく同じ処理をします。
- `book-store-tasks = n`（2以上。`auto` は `n-tasks`）では、n 局を同時に対局し（1局につき `n-tasks / n` スレッド）、終わったら n 局分の局面をまとめて上の 1〜3 の方法でbookに加えます。bookのLinkの張り直し・negamax・保存（`<bookファイル名>.store`）は、n 局につき1回です。対局中に読むbookは、その n 局を始める前のbookです（同じ組の中の棋譜の学習結果は、その組の対局には反映されません）。
- `book add` は、n 局分ずつ、探索を同時に行います。`book store` は、1局の局面の探索を同時に行います。
- Linkの張り直しで必要になるLeafの探索（`book fix`・`book merge`・`book import` など）も、この設定が1以外なら同時に行います（下の「book fix を速く」）。
- `book deviate`・`deviate2`・`deviate3`・`enhance`・`play`（`book-expand-tasks` を使います）と、`book fill` は変わりません。

- **仕組みが正しいことの確認**：従来の学習でも探索のたびにハッシュ表を空にする試験用ビルドを作り、同じ条件（探索1スレッド）で比べると、`book store`・`book add` でできるbookは、計画して同時に探索した場合と完全に一致しました。つまり、従来との違いは「探索ごとにハッシュ表を空にする」ことだけから生じます。ハッシュ表を空にすると、探索するノード数は約9%増えます（棋譜30本・level 18 での実測）。

**メモリ**：同時に動かす1スレッドの探索は、それぞれハッシュ表を持ちます。その大きさは、level 18 以下のとき1個14MB（19ビット）です（短い探索なので、21ビットの表と比べてノード数は0.7%増えるだけでした。`hash-table-size` の値にはよりません）。上の表の `auto` の722MBは、32個の探索の分（約450MB）と、プロンプト用の探索の表（226MB）、bookなどの合計です。

### book fix を速く（Linkの張り直しを複数スレッドで）

`book fix` は「局面の確認（Fixing）→ Linkの張り直し（Linking）→ negamax → 並べ替え（Sorting）」を行います（`book import`・`correct`・`prune`・`subtree` の後処理と同じ。`book subtree` は、v4.5.5-nikque.12 からLinkの張り直しを行いません。Linkの張り直しとnegamaxは `book store` の後にも行います）。これまで、確認・張り直し・並べ替えは1スレッドでした。これを複数スレッドにしました。

- **確認**：スレッドが手分けして局面を調べ、見つかった局面をbookの順に直します。壊れた局面（盤面が正規化されていない、など）を直すと、後の局面の判定が変わることがあるので、最初の壊れた局面からは従来どおり1つずつ調べ直します。
- **Linkの張り直し**：スレッドが手分けして「足りないLink」を探し（既にあるLinkの評価値の更新もここで行います）、Linkの追加はbookの順に行います。追加の途中で評価値が変わった局面へのLinkは、最後に従来と同じ値に直します。`book merge` の張り直しは、v4.5.5-nikque.6 までと同じ方法のままです（v4.5.5-nikque.3 から複数スレッドで、統合元のLeafを再利用します）。
- **張り直しで必要になるLeafの探索**：最善の未登録手（Leaf）がLinkになった局面は、Leafを探索し直します。`book-store-tasks` が1以外なら、探索が必要な局面と除く手を先に調べ、1スレッドの探索として同時に行います（棋譜の学習と同じ仕組み）。`1` なら、従来どおり1つずつ `n-tasks` の全スレッドで探索します。
- 確認と張り直しは、**1つずつ処理した場合と同じbookになります**。全bookコマンドの回帰試験と、わざと壊した10種類のbook（局面を間引いたもの、Linkを消したもの、評価値を書き換えたもの、盤面を裏返したものなど）で、結果が一致することを確かめました（探索は1スレッド）。Leafの探索を同時に行う場合も、探索のたびにハッシュ表を空にする試験用ビルドで1つずつ処理した結果と完全に一致しました（同じ10種類のbookと、level 18 の実bookでLinkを1000個外したもの、bookのmerge）。従来の探索（前の探索の結果がハッシュ表に残る・複数スレッド）とは、棋譜の学習と同じ理由で、探索し直したLeafがわずかに違うことがあります。
- 「局面の確認」の中で行うLeafの探索（Leafが壊れている局面の修復）は、従来どおり1つずつです。

実測（649万局面・286MBのbookを読み込んで `book fix`。秒）：

|---|---|---|---|
| 32スレッド：合計 | 25.4 | 22.9 | **2.3** |
| 　確認 / 張り直し / negamax | 0.1 / 22.4 / 2.9 | 2.2 / 20.5 / 0.2 | 0.2 / 1.9 / 0.2 |
| 1スレッド：合計 | 25.4 | 24.7 | 24.7 |

- 32スレッドで約10倍になりました。1スレッドでは v4.5.5-nikque.6 と同じ時間・同じメモリです。
- 上流より「確認」が長いのは、v4.5.5-nikque.2 から、bookにない局面へのLinkも調べているためです。
- 77万局面のbook（32スレッド）では、上流 2.3秒、v4.5.5-nikque.6 1.9秒、この版 0.1秒でした。

**Leafの探索が多い場合**（level 18 の実book 27万局面で、1000局面のLinkを1つずつLeafに戻してから `book fix`。Leafの探索が1000回必要です。32スレッド、`hash-table-size = auto`）：

- 約3倍の速さでした。できたbookは、探索ごとにハッシュ表を空にする試験用ビルドで1つずつ処理したbookと完全に一致します。
- **通常の `book merge` では、探索を同時に行う効果はほとんどありません。** 統合元のbookが同じlevelで探索したLeafを再利用するので、探索がほとんど要らないためです（同じbookに別々の棋譜64本ずつを学習した2つの実bookのmergeでは、908局面が増え、探索は1回。649万局面のbookを空のbookにmergeした場合で127回）。Leafの探索が多くなるのは、Linkが欠けたbookの `book fix` や、levelの違うbookのmergeなどです。


### libedax：Edaxをライブラリとして使う

[lavox氏のlibedax](https://github.com/lavox/edax-reversi)（[sensuikan1973氏の版](https://github.com/sensuikan1973/edax-reversi)）と同じ93個の関数を、このEdaxで使えるようにしました。libedax用に書かれたプログラム（[libedax4dart](https://pub.dev/packages/libedax4dart)、[edax_runner](https://github.com/sensuikan1973/edax_runner) など）が、ライブラリのファイルを差し替えるだけで動きます。

| ファイル | 対象のCPU |
|---|---|
| `libedax-x64.dll`（Linux：`libedax-x86-64.so`） | x86-64 のどのCPUでも動きます。libedax用のプログラムが読み込む名前です（Linuxでは `libedax.so` に名前を変えて置きます）。 |
| `libedax-x64-v3.dll`（`libedax-x86-64-v3.so`） | AVX2 対応のCPU |
| `libedax-x64-v4.dll`（`libedax-x86-64-v4.so`） | AVX-512 対応のCPU |
| `libedax.universal.dylib` | macOS（Apple silicon と Intel の両用）。 |
| `libedax-arm64-v8a.so`・`libedax-armeabi-v7a.so` | Android（ARM64・32ビットARMv7）。アプリに入れるときは `libedax.so` に名前を変えて、ABIごとのフォルダ（`jniLibs/arm64-v8a` など）に置きます。ビルドの確認だけで、実機での動作は確かめていません。 |

**ほかのプログラムから使うには**（[edax_runner](https://github.com/Nikque/edax_runner) のほか、自作のGUIや解析ツールなどから）：

1. 配布ZIPの `bin/` から、お使いのOS・CPU用のライブラリ（上の表）と `data/eval.dat`（必須）を取り出し、プログラムと同じフォルダに置きます（`data/book.dat` と `config.ini` は必要に応じて）。
2. C・C++ からは `src/libedax.h` を取り込みます。ほかの言語からは、その言語の外部関数呼び出し（FFI）でライブラリを読み込みます（Dart には [libedax4dart](https://pub.dev/packages/libedax4dart) があります。Python の ctypes、C# の P/Invoke などでも同じ関数を呼べます）。
3. 最初に `libedax_initialize` を呼び（設定を読みます）、`edax_init` で対局を始め、最後に `libedax_terminate` を呼びます。関数は edax のコマンドに対応しています（`edax_play`・`edax_go`・`edax_hint`・`edax_book_*` など。一覧は `src/libedax.h`、使い方の例は全関数を呼ぶ `tests/libedax_test.c`）。
4. 同時に使えるEdaxは、1つのプロセスにつき1つです（元のlibedaxと同じ）。関数は1つのスレッドから順に呼んでください（`edax_stop` と `edax_book_stop_count_bestpath` は、実行中の処理を止めるために別のスレッドから呼べます）。

短い例（`tests/libedax_example.c`。Windows と Linux でビルドして動作を確認しています）：

```c
#include <stdio.h>
#include "libedax.h"

int main(void)
{
	char *args[] = {"", "-eval-file", "data/eval.dat", "-book-file", "data/book.dat", "-level", "12", "-n-tasks", "2"};
	char moves[] = "f5d6c3";
	static LibedaxHintList hints;
	LibedaxMove last;
	int i;

	libedax_initialize(9, args);  /* edax.ini, config.ini, then these arguments */
	edax_init();                  /* new game */
	edax_play(moves);
	edax_hint(2, &hints);         /* the 2 best moves: hint[1] to hint[n_hints] */
	for (i = 1; i <= hints.n_hints; ++i)
		printf("%c%c %+d\n", 'a' + hints.hint[i].move % 8, '1' + hints.hint[i].move / 8, hints.hint[i].score);
	edax_go();                    /* Edax plays a move */
	edax_get_last_move(&last);    /* squares: A1 = 0, B1 = 1, ..., H8 = 63 */
	libedax_terminate();
	return 0;
}
```

- **関数と、呼び出し側とやり取りするデータの並びは元のlibedaxと同じです**（`src/libedax.h`）。Edax 4.5 で内部の構造が変わっているので、内部のデータをそのまま渡さず、元の並びのデータに詰め替えて渡します。
- **設定**は、作業フォルダの `edax.ini`、`config.ini`、`libedax_initialize` の引数の順に読みます（後のものが優先）。書き方と項目は edax 本体と同じです。
- 追加した関数：`edax_book_deviate2`、`edax_book_deviate3`（`book deviate2`・`deviate3`）、`libedax_cpu_level`（CPUが動かせる版を返します。`libedax-x64.dll` に問い合わせてから、v3・v4 を読み込む使い方ができます）、`edax_book_store_games`（複数の棋譜をまとめて対局・学習します。上の `book learn` と同じ処理で、棋譜は1行に1局の文字列で渡します）、`edax_book_store_tasks`（同時に学習する棋譜の数を返します。`book-store-tasks` が `auto` なら `n-tasks` の値）。v4.5.5-nikque.9 で `edax_book_save_checked`（bookを保存し、保存できたかどうかを返します）と `edax_book_failed`（直前のbookの処理が局面を追加できなかったかどうかを返します）を足しました。v4.5.5-nikque.12 で `edax_book_leaf_recalculate`・`edax_book_leaf_recalculate2`・`3`・`4`（`book leaf-recalculate` 系の命令）を足しました。

### 不具合の修正：学習の後、終了時にbookが保存されないことがある

v4.5.5-nikque.2 から、終了時のbookの保存は「最後に保存した後でbookが変わっているときだけ」にしています。ところが、学習コマンドが途中経過を別のファイルに保存したとき（`book store` の `.store`、`book deviate` の `.dev`・`.dev2`・`.dev3`、`book enhance` の `.enh`、`book play`、`book fill`、`book add` の `.gam`、`book deepen`、時間ごとの保存）にも「保存済み」になっていました。このため、たとえば `book store` の後に `book save` をせずに終了すると、学習した内容は `data/book.dat.store` にあるだけで、`data/book.dat` には保存されませんでした。途中経過の保存では「保存済み」にしないように直しました。`book save` で保存した場合と、何も変えていない場合は、従来どおり終了時に保存しません。

### book fix の途中経過の表示

`book fix`（`book import`・`correct`・`prune`・`subtree` でも使われます）の「Fixing book...」は、直す局面があったときしか途中経過を表示しなかったので、正常な大きなbookでは終わるまで何も表示されませんでした。確認した局面数を1秒ごとに表示します（例：`Fixing book...3137536/6491163 positions checked`）。bookの内容は変わりません。
## v4.5.5-nikque.6 の変更点

起動時の設定を `config.ini` で決められるようにし、合法手の数の上限を理論上の最大まで広げ、`book merge` の途中経過の表示を直しました。評価データ `eval.dat`、bookのファイル形式、同じオプションでの探索結果は変わりません。

### 起動時の設定（新しい設定と既定値）

`config.ini`（またはコマンドライン）で、起動時の次の4つの値を決められます。同梱の `config.ini` は次の値です。`config.ini` がない場合の既定値も同じです。

| 設定 | 同梱の値・既定値 | 意味 |
|---|---|---|
| `level` | `18` | 探索レベル（0〜60）。起動後は `level` コマンドで変えられます。 |
| `n-tasks`（`n`） | `auto` | 探索のスレッド数。1〜論理CPUの数、または `auto`（論理CPUの数）。 |
| `book-depth` | `auto` | bookの深さ（`book depth` コマンドと同じ）。`auto` はbookファイル（`data/book.dat`）に保存されている深さをそのまま使います。1〜60の数値を書くと、起動時にその深さにします（bookを保存するとファイルにも記録されます）。 |
| `book-usage` | `on` | bookから打つかどうか（`on`/`off`）。 |

- **組み込みの既定のlevelを21から18に変えました。** `-l` を指定しない `-solve` や対局の探索は、以前の版と違う結果になります。`-l` を指定した場合は同じです。
- **`config.ini`（と作業フォルダの `edax.ini`）に書いた `level` は、起動時のlevelだけを決めます。** 持ち時間制の対局（`-t`、`-move-time`）で読みの上限にはなりません（v4.5.5-nikque.5 の「持ち時間制ではlevelの上限を外しました」はそのままです）。上限にしたいときは、コマンドラインの `-l` か、Edaxのプロンプトの `level` で指定してください（`-o` で読ませる設定ファイルの `level` も、従来どおり上限になります）。
- コマンドラインでは `-n auto`、`-book-depth <n|auto>` と書けます。
- 設定の値は、Edaxのプロンプトの `options` で確かめられます（「book depth at startup」の行を追加しました）。bookの深さは `book info` の `Depth` です。

### config.ini の書き方を自由にしました

手で書き換えやすいように、`config.ini` と `edax.ini` の読み方を緩くしました。

- `level = 18`、`level=18`、`level 18`、`set level 18` はどれも同じです。`=` の前後の空白、タブ、全角の空白と全角の「＝」も使えます。
- 名前の大文字・小文字は区別しません。名前の中の空白・`_`・`-` も同じに扱います（`book-depth`、`book_depth`、`book depth`、`Book Depth` は同じ設定です）。
- 値の `on`/`off`/`auto`/`true`/`false`/`yes`/`no` も、大文字・小文字を区別しません。
- `=` を書いた場合は、行の残りが値になります（空白を含むファイル名も書けます）。
- `#` から行末まではコメントです。UTF-8 の BOM と CRLF の改行も問題ありません。
- 知らない名前（綴りの間違いなど）は、起動時にファイル名と行番号つきで警告します（例：`WARNING: config.ini:7: unknown or incomplete setting "levle" ignored`）。範囲外の値は、従来どおり警告して範囲内に収めます。

### 合法手の数の上限：33→34

1局面の合法手の数の上限（`MAX_MOVE`）を33から34にしました。初期局面から到達できる局面の合法手は最大33であることが示されています（[eukaryote 2023](https://eukaryote.hateblo.jp/entry/2023/05/23/145945)、[論文の紹介](https://othlog.hasera.net/20231112-2/)）。一方、到達できない局面も含めると合法手が34通りの局面が存在し、35通り以上はありません（[eukaryote 2020](https://eukaryote.hateblo.jp/entry/2020/04/13/150458)）。Edaxは `-solve` や `setboard` で任意の局面を受け付けるので、34通りの局面を入力されても手のリストがあふれないようにしました。

- 手のリスト（`MoveList`）は探索中の一時的な変数で、1つあたり32バイト増えるだけです（1スレッドあたり高々約2KB）。bookの局面（48バイト）と置換表には含まれないので、bookのメモリは変わりません。手の処理は実際の合法手の数だけ回るので、処理量も増えません。
- 1スレッドで、探索結果とノード数は変更前と完全に一致し、時間の差は測定のばらつきの範囲でした（level 18：0.995倍、中盤：1.008倍、終盤：1.002倍）。

### 不具合の修正：book merge・book fix の途中経過の表示

v4.5.5-nikque.3 でリンクと修正の処理を並列にしてから、`book merge` の「Linking book...」と「Fixing book...」が、最後の「done」まで途中経過を表示しなくなっていました（上流の版は10万局面ごとに表示していました）。1秒ごとに進み具合を表示するようにしました。bookの内容は変わりません。

- 局面の確認（並列）：`Linking book...3654055/6491163 positions checked`（確認した局面数/全局面数）
- リンクの追加と leaf の探索：`Linking book...16/17550 positions linked`（処理した局面数/対象の局面数）

- `book merge` でファイルを読む間も、大きなbookでは `Checking book ...` と `Merging book ...` に読んだ局面数を表示します（上流にはなかった表示です）。

### 持ち時間の使い方（対局）

- **持ち時間制ではlevelの上限を外しました。** 以前は、`-t`（1局の持ち時間）や `-move-time`（1手の持ち時間）で対局しても、既定のlevel 21に達すると読みをやめていました。1局16秒では持ち時間の約半分、1局64秒では2割未満しか使っていませんでした。levelを指定しない場合は上限を60にして、持ち時間まで読みます。`-l` や `level` でlevelを指定した場合は、従来どおりそのlevelが上限です。xboard の `sd`、NBoard の `depth` による指定も同じです。GTPは以前から上限60でした。

### book-expand-tasks = auto

`book-expand-tasks = auto`（同梱の `config.ini` の値。コマンドラインでは `-book-expand-tasks auto`）は、bookのlevelから同時に展開する局面の数を決めます。1局面の探索に、level 18 以下は2スレッド、24以下は4スレッド、それより上は8スレッドを使い、`n-tasks` をそれで割った数の局面を同時に展開します（32スレッド・level 18 なら16局面）。`config.ini` がない場合の既定は、従来どおり1です。計測したのは level 18（2スレッドずつが最速）だけです。できるbookは1局面ずつ展開した場合と同じにはなりません。下の v4.5.5-nikque.4 の「複数の局面を同時に展開する学習」の注意を読んでください。

### 実験的な設定：probcut-model = refit

探索の枝刈り（ProbCut：浅い探索の結果から深い探索の結果を予測して、見込みのない手を読まずに切る）の誤差モデルを、実測で当てはめ直したものです。既定は従来の `standard` で、`refit` は試験用です。

- 当てはめ：学習リストの棋譜から取った1200局面（空き24〜52）で、枝刈りなしの深さ0〜16（うち304局面は20まで）の評価値を求めました。浅い探索と深い探索の差は、深さにほとんどよらず、空きマスが多いほど小さくなりました（空き24で約2.4石、36で2.0石、48で1.4石）。従来のモデルは、深さとともに大きくなる式です。`refit` はこの当てはめた式を、従来の t の値（73%〜99%の各段階）を1.3倍にして使います。
- level 18 どうしの対局（2204局）：+3.5 [−4.4, +11.3]、別の開始局面で +16.5 [+8.3, +24.7]。時間は0.92倍でした。level 21 で +2.2（時間0.84倍）、level 24 で +10.0（時間0.86倍）です。
- 評価値の精度（level 26 の値を正解とした level 18 の評価値の平均絶対誤差、1200局面）：

| 空きマス | standard：誤差 / ノード | refit：誤差 / ノード |
|---|---|---|
| 24〜29 | 2.106 / 22.5億 | 2.186 / 16.6億 |
| 30〜35 | 1.986 / 6.5億 | 1.983 / 6.6億 |
| 36〜43 | 0.884 / 10.7億 | 0.859 / 12.5億 |
| 44〜52 | 0.632 / 3.7億 | 0.576 / 5.1億 |

序盤・中盤（空き36以上）では読む量が増えて評価値が少し正確になり、終盤寄り（空き24〜29）では読む量が減って少し不正確になります。bookの学習に使うと、序中盤の学習は遅くなり、できるbookも `standard` とは変わります。探索結果が変わるので、`standard` のbookと混ぜる前によく確かめてください。

### 強さの測り方と、採用しなかった変更

2つの版を、NBoardプロトコルで1102の互角の開始局面（ランダムな8手のうち level 18 の評価が±3以内のもの。別に10手の1087局面も使用）から、先手・後手を入れ替えて2局ずつ対局させました。Eloと95%信頼区間は、開始局面ごとの2局の組で計算しています。持ち時間の比較には、探索の時計をノード数で数える `-nps` を使いました。CPU負荷やコアごとの速さに左右されず、同じ条件なら結果が完全に再現します（このため `-nps` 指定時は、1局の残り時間もノード数で減らすように直しました）。

実力も速さも改善しなかったため、採用しなかった変更（1スレッド）：

- 深さ2の探索での手の並べ替え：ノード数は5.5%減りましたが、8〜13%遅くなりました。

### 複数の局面を同時に展開する学習（新しい設定）

低いlevelの探索は、多くのスレッドを使いきれません。level 18 の89局面では、32スレッドでも1スレッドの2.5倍の速さでした（4スレッドで2.1倍）。`book-expand-tasks = n`（`config.ini`、またはコマンドラインの `-book-expand-tasks n`）を指定すると、`book deviate`・`deviate2`・`deviate3`・`enhance`・`play` は n 局面を同時に展開します。それぞれ `n-tasks / n` 個のスレッドと専用のハッシュ表を使います。既定の1は、従来どおり1局面ずつ展開します。

実book（6億5688万局面）、`book deviate3 2 5` の最初の1万件の展開、32スレッド：

| `book-expand-tasks` | 展開の時間 |
|---|---|
| 1（2回） | 831.9秒、804.9秒 |
| 16（各2スレッド） | 173.8秒 |

3つのbookの局面とLinkの手は同じでした。Leafまたは評価値が違った局面は、1どうしの2回で258、16と1の各回で484と493でした。評価値の差はすべて1か2です。複数スレッドの探索は実行ごとに結果が揺れ、2スレッドの探索と32スレッドの探索では揺れ方も違います。また n が2以上では、同じ周の別の展開が同時に加えた局面（2つの局面が同じ子局面に行き着く場合など）を、新しい局面は参照しません。同時に展開する探索はそれぞれハッシュ表を持ちます（`hash-table-size = auto` ならそのスレッド数に合わせた大きさで、2スレッドなら各57MB）。

**`book-expand-tasks` を2以上にする前に：**

- **できるbookは、1局面ずつ展開した場合と同じではありません。** 上の試験では展開された局面とLinkの手は同じでしたが、一部のLeaf（まだLinkのない最善手）と評価値が1か2違いました。違いの件数は、32スレッドで1局面ずつ展開した2回どうしの約2倍です。
- **同時に展開している局面どうしは、お互いを参照しません。** 同じ周の2つの局面が同じ新しい局面に行き着く場合や、新しい局面が同じ周の別の新しい局面の子局面になる場合、その時点ではLinkが張られません（1局面ずつ展開すれば張られます）。後の周で張られることがあります。
- **効果は1周あたりの展開対象の数で変わります。** 各局面の探索は `n-tasks / n` 個のスレッドしか使いません。展開対象が n より少ない周では同時に動く探索も減り、1件だけの周は1局面ずつ展開します。
- **levelが高いほど、n は小さめにしてください。** 計測したのは level 18 だけで、1局面あたり2スレッド（32スレッドなら n = 16）が最も速くなりました。深い探索ほど1つの探索でスレッドを使えるので、高いlevelでは同時に展開する数を少なめ（32スレッドなら n = 4 や 8 など）から始め、速さを比べてください。
- **メモリ：** n 個の探索はそれぞれハッシュ表を持ちます（`hash-table-size = auto` ならそのスレッド数に合わせた大きさ、数値で指定した場合はその n 倍）。
- 途中保存（`book-save-interval`）は、書き込み中の局面が終わるのを待ってから行います。ほかの探索はそのまま続きます。
- `book-expand-tasks` は `n-tasks` を超えられません。学習中にEdaxで対局や解析もするときは、`n-tasks`（と `book-expand-tasks`）を減らしてください。

### ハッシュ表の大きさの設定

`hash-table-size = auto`（同梱の `config.ini` で使用。コマンドラインでは `-h auto`）は、探索のスレッド数からハッシュ表の大きさを選びます。1〜3スレッドは21、4〜15は22、16〜63は23で、上限は25、メモリの1/32までです。数値を書くと従来どおり固定の大きさ（2^n項目、3つの表で約27×2^nバイト）です。`config.ini` がない場合の既定は21のままです。`-h` を変えたときと同じく、大きさが変わると探索結果もわずかに変わります。32スレッド・level 18 と level 24 の試験では、23が21よりわずかに速く、それより大きくしても速くなりませんでした。

### 21億局面を超えるbook

bookのヘッダーの局面数を符号なし32ビットとして読み書きするようにし、4,294,967,295局面まで登録できるようにしました（以前は2,147,483,647）。以前の上限以下のbookは、これまでとバイト単位で同じに保存されます（実bookで確認：読み込み29秒・メモリ35.6GiBは従来どおり、保存したファイルは日時以外一致）。2,147,483,647局面を超えるbookは、以前の版や上流のEdaxでは読めません（局面数を不正として拒否します）。43億局面では約240GBのメモリが必要です。

大規模book（数億局面・数十GB）で `book deviate`・`book deviate2`・`book deviate3`・`book merge` を使うときの処理時間とメモリ使用量を改善し、11件の不具合を修正しました。また、`book merge` の後にbookを自動で保存する設定を追加しました。bookのファイル形式は変わっていません。以前のbookをそのまま読み書きできます。

### `book merge` の実測

6.57億局面・28.95GBの実bookに、別の実book（6.57億局面・29.03GB）をmergeしました（173.6万局面を追加）。公開された両版の `wEdax-x86-64-v4.exe` で、同じPC・同じbookを使い、1つずつ実行しています。

| 処理 | v4.5.5-nikque.2 | v4.5.5-nikque.3 | nikque.3 で再利用を無効にした場合（参考） |
|---|---|---|---|
| 起動時のbookのロード | 222秒 | 28秒 | 30秒 |
| `book merge` コマンド全体 | 16,408秒（4時間33分） | 263秒 | 10,934秒（3時間2分） |
| うちLinkの再構築 | 15,332秒 | 177秒 | 10,845秒 |
| merge後の `book save` | 251秒 | 18秒 | 62秒 |
| 起動から終了まで | 17,364秒（4時間49分） | 315秒 | 11,027秒 |
| ピークメモリ | 117.2GiB | 37.0GiB | 37.0GiB |

mergeにかかる時間の大半は、Linkの張り直しで最善の未登録手（Leaf）がLinkになった局面の探索し直しです（今回は約18.4万局面）。v4.5.5-nikque.3 は、統合元のbookが同じ探索レベルですでに探索している局面では、その結果を再利用して探索を省きます。これだけでmergeは約42倍速くなります（10,934秒→263秒）。再利用以外の改良（統合元を読み込まない処理、並列化など）による短縮は約1.5倍で、メモリはこちらの改良で117.2GiBから37.0GiBに減りました。

**再利用により、mergeの結果の評価値がわずかに変わることがあります。** 再利用するLeafの手は、探索し直した場合と同じ手になるはずですが、評価値は探索時のハッシュ表の状態や並列探索の進み方で変わることがあるためです。今回のmergeでは、6.59億局面のうち27,897局面（0.004%）で nikque.2 と評価値が異なりました。直接の差は14,200局面で、残りはその差が親局面へ伝わったものです。評価値の差はほとんどが1〜2です。局面の集合、Linkの手、勝敗の集計、探索レベルは完全に一致しました。なお、nikque.2 自身も探索し直す局面の評価値が実行ごとに揺れます。縮小した実book（3,484万局面）どうしのmergeでは、nikque.2 を2回実行しただけで1,655局面の評価値が異なり、nikque.2 と nikque.3 の差（約2,500局面）と同じ程度でした。

主な変更内容は次のとおりです。

- bookの読み書きを16MBのバッファ経由で行います（以前は1局面あたり約15回の小さな読み書き）。
- メモリ上の局面を64バイトから56バイトにしました。Linkが4個以下の局面（大規模bookの99%）は、Linkを別の領域に確保せず局面の中に置きます。
- Edaxが保存したbookは、ロード時に1つの領域へ隙間なく配置します（以前は配列の予備領域が約20%ありました）。
- negamax、deviate系の展開対象の選択、merge時のLinkの再構築・検査・並べ替えを、`n-tasks`（既定はCPU数）のスレッドで並列に処理します。並列処理でも結果は同じです。
- 各周の「全局面の印を消す」処理と「展開対象を探す全局面走査」をなくしました。展開の順序は以前と同じです。
- `book merge` は統合元のbookを読み込まず、ファイルを2回読みます（1回目で全体を検査、2回目で局面を追加）。統合元が壊れている場合は統合先を変更しません。統合元がすでに探索済みの局面については、その結果（最善の未登録手）を再利用し、探索をやり直しません（評価値がわずかに変わることがあります。上の「`book merge` の実測」を参照）。

book学習と同時に対局や解析を行う場合は、`n-tasks`（`-n`）でスレッド数を指定できます。

### merge後の自動保存（新しい設定）

`bin/config.ini` の `book-merge-auto-save` が `on`（既定）のとき、`book merge` が成功すると、統合後のbookを `<bookファイル名>.mrg`（既定では `data/book.dat.mrg`）に自動で保存し、`Merged book saved to data/book.dat.mrg` と表示します。`book save` を別に実行する必要はありません。保存先のファイル名は、deviate系の進捗ファイル（`.dev`・`.dev2`・`.dev3`）と同じく、設定されたbookファイル名に拡張子を付けたものです。`book load` で別のbookを開いている場合も同じ名前になります。

- `.mrg` を使うには、`book load data/book.dat.mrg` で読み込むか、ファイル名を変更してください。元のbook（`data/book.dat`）は自動保存では上書きしません。
- mergeが失敗した場合（統合元が存在しない・壊れているなど）は保存しません。
- 終了時の保存は以前と同じです。merge後に `book save` をせずにEdaxを終了すると、以前と同様に設定されたbookファイル（`data/book.dat`）へ保存されます。
- `off` にすると、`.mrg` の保存と表示を行わず、以前とまったく同じ動作になります。コマンドラインの `-book-merge-auto-save off` でも指定できます。

## bookの学習と保守

bookを読み込んだEdaxのコマンド入力画面で、次のコマンドを使います。いずれも現在の局面から登録済みLinkをたどり、条件に合うLeafを展開します。Leafは次の局面へのLinkがない候補手であり、bookに存在しない任意の手を列挙するわけではありません。設定されたbook深さで止まり、新しい局面やLinkがなくなるまで展開を繰り返します。

| コマンド | 対象とする条件 | 主な用途 |
|---|---|---|
| `book deviate 2 4` | 従来の相対誤差と開始局面からの絶対誤差。従来の選択条件を維持。 | 従来の学習方法を続ける場合。 |
| `book deviate2 5 5` | 一手の評価損失は最大5、黒白合計も最大5。bookの学習レベルで完全読み済みのLeafを除外。 | 完全読み済みLeafの再学習を避ける場合。 |
| `book deviate3 5 5` | 一手・累積の制限はdeviate2と同じで、完全読み済みLeafも含む。 | 以前のdeviate2と同じ対象を選ぶ場合。 |

`deviate2` と `deviate3` では、黒2石・白3石の損失や一手で5石の損失は範囲内、一手で6石または合計6石の損失は範囲外です。表示される `todo` はその回に選ばれたLeaf局面の件数であり、異なる棋譜の本数ではありません。進捗bookには、設定されたbookファイル名に応じて `.dev`、`.dev2`、`.dev3` が付きます。

`bin/config.ini` には、3種類のdeviateコマンドに適用する独立した保存条件が2つあります。`book-save-interval` は展開中の時間間隔による保存（分）で、`0` はこれを無効にします。`book-deviate-save-rounds` は増分があった完了済みの周回数で、`1` は従来どおり毎周、`10` は10周ごとと学習完了時、`0` は時間間隔による保存を除き学習完了時だけ保存します。従来の `book deviate` は黒白両方の展開で1周、`deviate2/3` は1回の展開で1周です。失敗や中断時には最後の保存以降の学習内容が失われる可能性があり、特に `0` と時間保存の無効化を組み合わせた場合は注意が必要です。互換性のため初期値は `1` です。

### 従来の `book deviate` の修正

従来の `book deviate` には、ポインタの寿命に関するバグがありました。最初の `book_expand` 中に呼ばれる `book_add` は、ハッシュバケットの `Position` 配列を `realloc` で移動させることがあります。従来はその後の2回目の `position_deviate` に古い `root` ポインタを渡しており、解放済み領域を読んで学習が中断したり、局面が欠落したりする可能性がありました。現在は展開後に開始局面からrootを取り直します。従来コマンドの選択条件は変更していません。既存bookの欠落局面を自動で補う修正ではありません。

### `book merge` と `book fix`

bookを統合するには、統合先のbookを読み込んで `book merge source.dat` を実行します。`book-merge-auto-save = on`（既定）なら結果は `<bookファイル名>.mrg` に自動で保存されます。別の名前で残す場合や `off` の場合は `book save merged.dat` で保存します。mergeは統合元にしかない局面を追加し、統合先に既にある局面は上書きしません。続いてLinkの再構築、不整合な局面（古い `nomove` Leafを含む）の修復、評価値の再計算、着手の並べ替えを行います。Linkの張り直しで統合先の局面のLeafが空になった場合、統合元の同じ局面のLeafがまだLinkになっていなければそれを使い、そうでなければ探索します。現在のbookを単独で修復する `book fix` も利用できますが、このmerge手順の前提条件ではありません。統合元のファイルが存在しない、または構造が壊れている場合、mergeを中止し現在のbookを維持します。merge中のメモリ使用量は統合先のbookの分だけです。

book保存時は、一時ファイルへの書き込みをディスクに確定させてから保存先を置き換えます。保存に失敗しても旧bookを保持しますが、保存中はbookとほぼ同じ容量の追加空き領域が必要です。

| 対局と持ち時間 | XBoardの `level 0` でのゼロ除算防止、着手後のFischer加算、棋譜解析履歴の境界確認とパス履歴の初期化。 |
| PGNとGGF | 密なFEN・最大長GGFフィールド用の領域確保、PGNのFENタグと時刻タグの往復、PGN読込を最大60着手に制限。 |
| コマンドと通信 | パーサーの出力先サイズと短いファイル名の処理、GTP `reg_genmove` の結果返却、`time_left` の色検証と応答IDの初期化、NBoardの数値型に合った表示。 |

## 設定（config.ini）

Edaxは次の順に設定を読み、後のものが前のものより優先されます。

1. 作業フォルダの `edax.ini`（あれば）
2. 実行ファイルと同じフォルダの `config.ini`（配布物では `bin/config.ini`）
3. コマンドラインのオプション

ファイルの各行は `名前 = 値` の形で、`#` から行末まではコメントです（書き方の自由度は v4.5.5-nikque.6 の「config.ini の書き方を自由にしました」を参照）。コマンドラインのオプションは、先頭の `-` を除いた長い名前で、どれでもこのファイルに書けます（`-n 16` なら `n-tasks = 16`、`-l 18` なら `level = 18`、`book-file = data/book.dat` など）。Edaxのプロンプトで `名前 値`（例：`book-expand-tasks 16`、`n-tasks 16`）と入力すると、次の探索や学習コマンドから設定が変わります。ただし `hash-table-size` は起動時の値だけが有効です。

### 同梱の config.ini の設定

| 設定 | 同梱の値 | 意味 |
|---|---|---|
| `level` | `18` | 起動時の探索レベル。持ち時間制の対局では上限になりません（上の v4.5.5-nikque.6 の説明を参照）。 |
| `n-tasks` | `auto` | 探索のスレッド数（`auto` は論理CPUの数）。 |
| `book-depth` | `auto` | 起動時のbookの深さ（`auto` はbookファイルの値のまま）。 |
| `book-usage` | `on` | bookから打つかどうか。 |
| `book-save-interval` | `360` | 学習中にbookを時間で途中保存する間隔（分）。`0` なら時間では保存しません。 |
| `book-deviate-save-rounds` | `1` | `book deviate`・`deviate2`・`deviate3` で、局面が増えた周をこの数だけ終えるごとに保存します（`0` は学習の終了時だけ）。 |
| `book-merge-auto-save` | `on` | `book merge` が成功するたびに、bookを `<bookファイル名>.mrg` に保存します。 |
| `hash-table-size` | `auto` | 探索用ハッシュ表の大きさ（下記）。 |
| `book-expand-tasks` | `auto` | 学習コマンドで同時に展開する局面の数（下記）。 |
| `book-store-tasks` | `auto` | `book store`・`book add`・`book learn`（とedax_runner）で同時に学習する棋譜の数（下記）。 |
| `book-leaf-recalculate-rounds` | `1` | `book leaf-recalculate`（と `2`・`3`・`4`）を繰り返す回数の上限（下記）。 |
| `probcut-model` | `standard` | 探索の枝刈り（ProbCut）の誤差モデル。`refit` は実験用（上の v4.5.5-nikque.5 の説明を参照）。 |

そのほかによく使う設定：`book-file` と `eval-file`（ファイルの場所）。コマンドラインの `-l`（とプロンプトの `level`）で指定したlevelは、持ち時間制の対局で読みの上限になります。

### hash-table-size

探索は、探索済みの結果を3つのハッシュ表に記録します。`hash-table-size = n` で主表は2^n項目（1項目24バイト）、小さい2つの表は各2^(n-4)項目になり、合計は約27×2^nバイトです。

| n | 21 | 22 | 23 | 24 | 25 | 26 | 27 | 28 | 30 |
|---|---|---|---|---|---|---|---|---|---|
| メモリ | 57MB | 113MB | 226MB | 453MB | 906MB | 1.8GB | 3.6GB | 7.2GB | 29GB |

指定できる値は10〜30です（32ビット版は10〜25）。`auto` は、探索のスレッドが1〜3なら21、4〜15なら22、16〜63なら23を選びます。上限は25で、メモリの1/32までです。`config.ini` がない場合の既定は21です。

- bookの学習と対局には `auto` をおすすめします。32スレッドの level 18 と level 24 の試験では、23が21よりわずかに速く、それより大きくしても速くなりませんでした。
- 長い探索（深い解析、空きマスの多い終盤の完全読み）では、大きい表が役立つことがあります。v4.5.5-nikque.4 からは、bookの局面を探索するたびに表を書き換えなくなったので、大きい表でbookの学習が遅くなることもなくなりました。
- 表の大きさが変わると、探索結果もわずかに変わります。結果を正確に再現したいときは、同じ数値（と同じ `n-tasks`）を指定してください。
- `book-expand-tasks = n` では、n 個の探索がそれぞれ表を持ちます。`auto` ならそれぞれの探索のスレッド数に合わせた大きさ、数値ならどの探索もその大きさです。`book-expand-tasks = auto` が1スレッドの探索を `n-tasks` 個動かす周（v4.5.5-nikque.10 から）の表は、1スレッドの探索の上限（level 18 までは19ビット、21までは20ビット、それより上は21ビット）までで、かつ2スレッドの探索の表の半分までです（いちばん小さい10ビットより小さくはしません。半分までにするのは v4.5.5-nikque.13 から。探索の数が2倍でも、表の合計が増えないようにするため）。

### book-expand-tasks

`book-expand-tasks = 1`（`config.ini` がない場合の既定値）では、学習コマンド（`book deviate`・`deviate2`・`deviate3`・`enhance`・`play`）は、選んだ局面を1つずつ、`n-tasks` の全スレッドで探索して展開します。以前とまったく同じ動作です。`book-expand-tasks = n` では n 局面を同時に展開し、それぞれ `n-tasks / n` 個のスレッドを使います。

`book-expand-tasks = auto`（同梱の値）は、bookのlevelから n を決めます（1局面の探索に level 18 以下は2スレッド、24以下は4、それより上は8。n は `n-tasks` をそれで割った数）。

**v4.5.5-nikque.10 から**、level 18 以下で、その周の展開の対象が `n-tasks` の32倍以上（32スレッドなら1,024件以上）のときは、1スレッドの探索を `n-tasks` 個動かします（上の「v4.5.5-nikque.10 の変更点」）。それより対象の少ない周は、ここに書いたとおりです。

低いlevelの探索は多くのスレッドを使いきれません。level 18 では、32スレッドでも1スレッドの2.5倍の速さでした。複数の局面を同時に展開すると、残りのスレッドも働きます。32スレッド・level 18 の実bookでは、`book-expand-tasks = 16` で学習が4.7倍速くなりました。できるbookは1の場合と同じにはならないので、使う前に上の「複数の局面を同時に展開する学習」の注意を読んでください。

最初に試す値の目安（お使いのbookとlevelで速さを確かめてください）：

| 用途 | `n-tasks` | `book-expand-tasks` | `hash-table-size` |
|---|---|---|---|
| 対局・解析、または以前と同じ動作で学習したい場合 | 全CPU（既定） | 1 | auto |
| 論理CPU 32のPCで、level 18 以下のbook学習 | 32 | auto（=16、各2スレッド） | auto |
| 論理CPU 32のPCで、より高いlevelのbook学習 | 32 | auto（level 24 以下で8、それより上で4）、または速さを比べて4〜8 | auto |
| ほかの作業をしながらbook学習 | CPUの半分程度 | `n-tasks` の半分以下 | auto |

32スレッドのPCで level 18 のbookを学習する `config.ini` の例：

```
book-save-interval = 360
book-deviate-save-rounds = 1
book-merge-auto-save = on
n-tasks = 32
hash-table-size = auto
book-expand-tasks = auto
```

### book-store-tasks

`book-store-tasks = auto`（同梱の値。`config.ini` がない場合の既定値も同じ）では、`book store`・`book add`・`book learn` は `n-tasks` 本の棋譜を同時に学習します（1本につき1スレッド）。数値 n（2以上）では n 本を同時に学習します（仕組みと実測は、上の「棋譜の学習を複数のスレッドで」を参照）。`book-store-tasks = 1` では、棋譜の局面を1つずつ、`n-tasks` の全スレッドで探索します。v4.5.5-nikque.6 までとまったく同じ動作で、できるbookも同じです。

- **速さ**：`auto` が最も速く、上の実測（論理CPU 32、level 18）では `1` の2.8〜3.3倍でした。8や16を指定するより `auto` のほうが速く、メモリも少なく済みます。
- **できるbook**：`auto`（と2以上の数値）のbookは、`1` の場合と同じにはなりません（探索ごとにハッシュ表を空にすることと、同じ組の棋譜が互いの学習結果を使わずに対局することによる違い）。違いの大きさは上の表を参照してください。以前の版と同じbookを作りたいときは `1` を指定します。v4.5.5-nikque.8 からは、途中でスレッドを足した探索があるので、`auto` のbookも実行のたびにわずかに変わることがあります（27万局面で7局面）。
- **Linkの張り直し中のLeafの探索**（`book fix`・`book merge`・`book import` など）も、この設定が1以外なら、1スレッドの探索として同時に行います。
- **メモリ**：局面の探索は、探索を `n-tasks` 個まで同時に動かし、それぞれがハッシュ表を持ちます。探索の数が `n-tasks` より少ないときは、1つの探索に複数のスレッドを使い、ハッシュ表もその分大きくします（合計は、1スレッドの探索を `n-tasks` 個動かす場合を超えません）。1スレッドの探索の1個の大きさは、level 18 以下で14MB（19ビット）、level 21 以下で28MB、それより上は57MBです。`hash-table-size` の値にはよりません（探索が `n-tasks` 個あるので、大きな数値をそのまま使うとメモリが足りなくなるためです。これより小さい数値を指定した場合だけ、その大きさになります）。`n` が `n-tasks` より小さいときは、同時に対局する n 個の探索（それぞれ `n-tasks / n` スレッド）のハッシュ表も加わります。
- edax_runner（このforkのlibedaxを使う版）は、この設定が1以外のとき、学習リストの「Edax対Edax」の行をこの数ずつまとめて学習します。

### book-leaf-recalculate-rounds

`book-leaf-recalculate-rounds = 1`（同梱の値。`config.ini` がない場合の既定値も同じ）では、`book leaf-recalculate`（と `2`・`3`・`4`）は1回たどって終わります。n（2以上）では、「たどる → Leafを計算し直す → negamax」を最大 n 回繰り返し、Leafが1つも変わらなかった回で終わります。Leafを計算し直すと評価値が動き、命令がたどる範囲も動くので、範囲の中のLeafを全部新しい値にするには繰り返しが要ります（上の「v4.5.5-nikque.13 の変更点」）。

### book-store-auto-save

`book-store-auto-save = on`（既定。同梱の `config.ini` には書いていません）では、`book store` と、`book learn` の1組（`book-store-tasks` 本）の学習が終わるたびに、bookを `<bookファイル>.store`（例：`data/book.dat.store`）に保存します。これまでの版と同じ動作です。`off` では、この保存を行いません（bookは、`book save` か終了時の保存で、bookファイルに保存されます）。v4.5.5-nikque.9 で足しました。`config.ini` に `book-store-auto-save = off`、またはコマンドラインに `-book-store-auto-save off` と書きます。edax_runner（v5.3.0-nikque.3）は、学習のたびに自分で `book.dat` を保存するので、この設定を自分で `off` にします。

bookのメモリはこれらの設定によらず、1局面あたりLinkを含めて約50バイトです（6.57億局面で30.6GiB。v4.5.5-nikque.4 までは約58バイト・35.6GiB）。これにハッシュ表の分（上の例では16×57MB＝約0.9GB）と、`book deviate`・`deviate2`・`deviate3` の局面選択中だけ1局面1バイトの表が加わります。

## ビルドと利用

この系列（v4.5.5-eval2.1・v4.5.5-eval2.2）の配布一式には、この系列の評価データ `bin/data/eval.dat`（版 3.3.0、SHA-256 `1870f8fa5eecb6df972a4d83224832f9a620745cdc67c2d9b17bcd0ba09ea172`。上の「v4.5.5-eval2.1 の変更点」を参照）と、[元forkのv4.5.5配布物](https://github.com/okuhara/edax-reversi-AVX/releases/tag/v4.5.5)からそのまま取り出した初期book `bin/data/book.dat`、問題集を同梱します。上流の `eval.dat`（SHA-256 `f8b2299612d9fa4414157e70e932636e33111c2602d0c2fc382a7d90ef21b792`）は、v4.5.5-nikque.9 までの配布一式に入っています。既定の `data/eval.dat` を参照できるよう、実行ファイルは `bin/` から起動するか、`-eval-file` でファイルを指定してください。配布ZIPには次の実行ファイルが入っています。

| Windows 32-bit x86：標準 / SSE2 | `wEdax-x86.exe` / `wEdax-x86-sse.exe` |
| Windows ARM64 | `wEdax-arm64.exe` |
| Linux x86-64：標準 / AVX2 / AVX-512 | `lEdax-x86-64` / `lEdax-x86-64-v3` / `lEdax-x86-64-v4` |
| Linux 32-bit x86 | `lEdax-x86` |
| macOS Intel x86-64 / Apple silicon（arm64） | `mEdax-x64-modern` / `mEdax-arm64` |
| Android ARM64 / 32-bit ARMv7 | `aEdax-arm64-v8a` / `aEdax-armeabi-v7a` |
| ライブラリ（libedax）Windows x86-64：標準 / AVX2 / AVX-512 | `libedax-x64.dll` / `libedax-x64-v3.dll` / `libedax-x64-v4.dll` |
