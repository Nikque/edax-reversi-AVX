# 5. 探索の基礎

[目次](README.md) ｜ 前：[4. 設定](04-settings.md) ｜ 次：[6. book の基礎](06-book-basics.md)

Edax は、手を決めるときも、ヒントを出すときも、book を育てるときも、「探索」（先を読むこと）をします。この章は、探索の強さを決める **level**、表示に出てくる **深さ** と **%**、**スレッド**、**ハッシュ表**の説明です。book を育てる人にとっては、「book の level とは何か」を理解するための章でもあります。

## 5.1 探索の表の読み方

`hint` や `go` を行うと、次のような表が出ます。

```
 depth|score|       time   |  nodes (N)  |   N/s    | principal variation
------+-----+--------------+-------------+----------+----------------------
18@73%  +00        0:00.110      15578834  141625764 c3 D3 c4 F4 c5 B3 c2 E3
18@73%  -01        0:00.000         15137            c4 F4 f6 G5 f3 D3 c3 G6
------+-----+--------------+-------------+----------+----------------------
```

| 欄 | 意味 |
|---|---|
| `depth` | 読んだ深さ（何手先まで読んだか）。`18@73%` は「18 手先まで、確かさ 73% の読み方で」。`@` がなければ 100%（5.3） |
| `score` | 評価値。手番の側から見た、最後の石差の見込み。`+` なら手番の側が良い |
| `time` | かかった時間（分:秒） |
| `nodes (N)` | 調べた局面の数（ノード数） |
| `N/s` | 1 秒あたりのノード数（速さ）。時間が短すぎるときは空欄 |
| `principal variation` | 読み筋。両者が最善を尽くしたときの手順の予想。**黒の手が小文字、白の手が大文字** |

`score` の数字の前に、印が付くことがあります。

| 印 | 意味 |
|---|---|
| （なし） | その深さで求まった値 |
| `<` | 「この値以下」としか分かっていない |
| `>` | 「この値以上」としか分かっていない |
| `?` | 途中で止めたなどで、確かでない値（`stop` で止めたときなど） |

## 5.2 level とは

**level** は、探索の強さを決める 0〜60 の数です。level が決まると、局面の「空きマスの数」に応じて、**どこまで深く・どのくらいの確かさで読むか**が決まります。

考え方は次のとおりです。

- **序盤・中盤**（空きが多い）：最後までは読めないので、**level の数だけ先まで**読みます（level 18 なら 18 手先）。読んだ先の局面は、評価データ（`eval.dat`）で点を付けます。だから評価値は「見込み」です。
- **終盤**（空きが少ない）：**終局まで全部**読みます。確かさが 100% なら、評価値は正確な石差です。これを**完全読み**と言います。
- その間：終局まで読みますが、確かさを少し落として（下の「%」）速く読みます。

level 18（配布物の設定）では、次のようになります。

| 空きマスの数 | 読み方 | 表示の例 |
|---|---|---|
| 28 以上 | 18 手先まで、73% | `18@73%` |
| 25〜27 | 終局まで、87% | `26@87%` |
| 22〜24 | 終局まで、98% | `23@98%` |
| 21 以下 | 終局まで、100%（**完全読み**） | `20` |

つまり level 18 の Edax は、空きが 21 以下になれば、必ず正確な結果を知っています。

### level ごとの表

「完全読みになる空きの数」と「中盤で読む深さ」を、level ごとにまとめます（ソースの式から作った表です）。

| level | 中盤の読み方（その空きの数以上で） | 終局まで読むが確かさが 100% 未満の範囲 | 完全読みになる空き |
|---|---|---|---|
| 1〜10 | level 手先まで、100%（空きが level×2 より多いとき） | なし | level×2 以下 |
| 11・12 | level 手先まで、73%（空き 25 以上） | 22〜24：98% | 21 以下 |
| 13〜18 | level 手先まで、73%（空き 28 以上） | 25〜27：87%、22〜24：98% | 21 以下 |
| 19〜21 | level 手先まで、73%（空き 31 以上） | 28〜30：87%、25〜27：98% | 24 以下 |
| 22〜24 | level 手先まで、73%（空き 34 以上） | 31〜33：73%、28〜30：95%、25〜27：99% | 24 以下 |
| 25〜27 | level 手先まで、73%（空き 34 以上） | 31〜33：87%、28〜30：98% | 27 以下 |
| 28・29 | level 手先まで、73%（空き 37 以上） | 34〜36：73%、31〜33：95%、28〜30：99% | 27 以下 |
| 30・31 | level 手先まで、73%（空き 37 以上） | 34〜36：87%、31〜33：98% | 30 以下 |
| 32・33 | level 手先まで、73%（空き 40 以上） | 37〜39：73%、34〜36：95%、31〜33：99% | 30 以下 |
| 34・35 | level 手先まで、73%（空き 40 以上） | 37〜39：87%、34〜36：98%、31〜33：99% | 30 以下 |
| 36〜59 | level 手先まで、73%（空きが level＋10 以上） | 3 マスごとに 73%・87%・95%・98%・99% と上がる | level−6 以下 |
| 60 | （なし） | なし | いつでも（初手から完全読み） |

- level 0 は、先を読みません。打てる手のどれにも同じ評価値が付き、その中から、でたらめに 1 つが選ばれます（打つたびに変わります）。
- level 1〜10 は、確かさを落とさずに level 手先まで読みます。level 11 以上の中盤は、73% の読み方です。
- **level を上げると、時間は急に増えます。** かかる時間は、局面と PC で大きく変わります。試した PC（Ryzen 9 9950X）では、序盤の局面の 1 手が、level 18・32 スレッドで 0.1 秒ほど、level 40・2 スレッドで約 10 秒でした。対局が進んで「終局まで読む」範囲（上の表のまん中と右の欄）に入ると、高い level では、さらに長くなります。少しずつ上げて、確かめてください。
- level 60 は、どの局面でも終局まで読もうとします。空きの多い局面では、とても長い時間がかかります（終わるまで待てないことがあります）。

## 5.3 「%」（確かさ）とは

Edax は、探索を速くするために、「この枝は、深く読んでも結果を変えそうにない」と見込んだ枝を、浅い読みだけで打ち切ります。この見込みの厳しさが **%** です。

| 表示 | 意味 |
|---|---|
| `@73%` | いちばん大胆に打ち切る（速いが、見落としがあり得る） |
| `@87%`、`@95%`、`@98%`、`@99%` | だんだん慎重になる |
| （`@` なし＝100%） | 見込みでの打ち切りをしない |

- 「73%」は「100 回に 27 回まちがう」という意味ではありません。打ち切りの判定 1 回ごとの見込みの強さを表す数で、探索全体の結果が正しい確率ではありません。
- **終局まで読んで、かつ 100%** のときだけが、正確な結果（完全読み）です。`25@87%` のように、深さが空きの数と同じでも `@` が付いていれば、「たぶんこの石差」という値です。

## 5.4 時間で考えさせる

`game-time`（1 局の持ち時間）や `move-time`（1 手の時間）を指定すると、Edax は level ではなく時間で、読む深さを決めます（[3.8](03-playing.md)）。浅い読みから 1 手ずつ深くしていき、時間が来たところで、そこまでの結果を使います。このときの表示は、たとえば次のようになります（持ち時間 20 秒、空き 58 の局面）。

```
32@73%  -02        0:01.250      60118065   48094452 c3 D3 c4 F4 f6 F3 e6 E7
```

## 5.5 スレッド（n-tasks）

`n-tasks` は、探索に使うスレッドの数です。配布物の設定は `auto`（その PC の論理 CPU の数）です。

- スレッドを増やすと探索は速くなりますが、**数に比例はしません**。短い探索ほど、多くのスレッドを使いきれません。配布物の README の実測（level 18 の 89 局面、Ryzen 9 9950X・論理 CPU 32）では、32 スレッドでも 1 スレッドの 2.5 倍（4 スレッドで 2.1 倍）でした。深い探索（高い level、空きの多い完全読み）ほど、スレッドの効果が出ます。
- ほかの作業をしながら使うときは、`n-tasks` を減らすと、PC が重くなりにくくなります。
- book を育てるときに多くのスレッドを生かす方法は、別にあります（1 つの探索に全部のスレッドを使うのではなく、複数の局面を同時に探索する。[7 章](07-book-learning.md)・[9 章](09-large-books.md)）。

## 5.6 ハッシュ表（hash-table-size）

Edax は、探索で調べた局面の結果を**ハッシュ表**に覚えておき、同じ局面にもう一度来たときに使い回します。`hash-table-size = n` と書くと、主な表が 2 の n 乗個の項目を持ち、使うメモリは全部で約 27×2^n バイトです。

| n | 21 | 22 | 23 | 24 | 25 | 26 | 27 | 28 | 30 |
|---|---|---|---|---|---|---|---|---|---|
| メモリ | 57MB | 113MB | 226MB | 453MB | 906MB | 1.8GB | 3.6GB | 7.2GB | 29GB |

- 指定できるのは 10〜30（32 ビット版は 10〜25）です。
- **`auto`（配布物の設定）をおすすめします。** スレッドの数から、1〜3 スレッドなら 21、4〜15 なら 22、16〜63 なら 23 を選びます（上限は 25。PC のメモリの 1/32 まで）。
- 長い探索（高い level、空きの多い完全読み）では、大きい表が役に立つことがあります。短い探索では、大きくしても速くなりません（README の実測：32 スレッドの level 18・24 では、23 が 21 よりわずかに速く、それより大きくしても速くならなかった）。
- 実行中に `hash-table-size 24` のように打つと、表は、その大きさで作り直されます（v4.5.5-nikque.13 から。それより前の版では、起動のときの値だけが使われていました）。

## 5.7 同じ結果になるか

- **1 スレッド**（`n-tasks = 1`）で、同じ局面・同じ level・同じ `hash-table-size` なら、Edax は毎回同じ結果を出します（評価値・手・読み筋・ノード数）。実行ファイルの種類（標準・`v3`・`v4`）が違っても、結果は同じです。
- **複数スレッド**では、実行のたびに、結果が少し変わることがあります（スレッドの動く順番が毎回違うため）。多くは「同じ評価値の手のうち、どれを選ぶか」と、確かさが 100% でない探索の評価値の 1〜2 石の違いです。完全読み（100%）では、配布物の README の確認（終盤の問題集を 32 スレッドで 2 回ずつ）で、評価値は一致し、違ったのは同点の手の選び方だけでした。
- `hash-table-size` を変えると、確かさが 100% でない探索の結果が、わずかに変わることがあります。

結果を正確に再現したいとき（検証など）は、`n-tasks = 1` にして、`hash-table-size` を数で指定してください。

## 5.8 評価値について知っておくこと

- 評価値は**石差**です。`+4` は「手番の側が 4 石勝つ見込み」。引き分けは `+0`。
- 中盤の評価値は、level が違えば変わります。深く読むほど正確になる、というのがふつうですが、level 18 の `+2` と level 24 の `+0` のどちらが正しいかは、最後まで読まないと分かりません。
- 評価値を正確にしたいなら、完全読みになる空きの数まで進めるか、level を上げます。
