## 10.1 棋譜の形式

Edax は、棋譜のファイルの形式を、**ファイル名の終わり（拡張子）**で決めます。

| 拡張子 | 形式 | 1 局を保存・読み込み（`save`・`load`） | 棋譜の束（`book add`・`base …`） |
|---|---|---|---|
| `.txt` | 文字。1 行に 1 局 | ○ | ○ |
| `.ggf` | GGF（インターネットの対局サーバー GGS の形式） | ○ | ○ |
| `.sgf` | SGF | ○ | ○ |
| `.pgn` | PGN | ○ | ○ |
| `.wtb` | WTHOR のデータベース | × | ○ |
| `.edx` | Edax 独自のバイナリー | ○ | ○ |
| `.eps`・`.svg` | 盤の図（`save` で書き出すだけ） | 保存だけ | × |

### 文字の形式（.txt）

いちばん簡単で、手で書くのにも向いています。1 行が 1 局で、手を続けて書きます。

```
F5D6C3D3C4F4C5B3C2
f5f6e6f4e3c5c4e7c6e2
```

- 大文字でも小文字でもかまいません。Edax が書き出すときは、大文字になります。
- パスは書きません（必要なところで、自動で入ります）。
- ふつうの初期局面以外から始まる対局（`setboard` の後の対局）を `.txt` に保存すると、手順の前に、最初の局面が `盤 手番;` の形で書かれます。

  ```
  -------------------O-------OO------XO--------------------------- X;D2C3
  ```

  **ただし、この形の行は、読み戻せません**（`.txt` の読み込みは、いつもふつうの初期局面から始まる手順として読みます。この行を `load` すると、`WARNING: game text: … is not a move that can be played here` という警告が出て、1 手も読まれず、ふつうの初期局面の、手のない対局になります。それまでの対局は消えます）。途中の局面から始まる対局を残すときは、下の表の形式を使ってください。

### 途中の局面から始まる対局を保存するとき

同じ対局（`setboard` で作った局面から 2 手）を 5 つの形式で保存し、読み戻して確かめた結果です。

| 形式 | 読み戻した結果 |
|---|---|
| `.ggf`・`.pgn`・`.edx` | 最初の局面も手順も、元どおり |
| `.txt` | **読み戻せない**。1 手も読まれず、ふつうの初期局面の、手のない対局になる（警告が表示される） |
| `.sgf` | **読み戻せない**。`WARNING: error while importing a SGF game` と表示され、読み込まれない（盤は、`load` の前のまま） |

ふつうの初期局面から始まる対局は、どの形式でも読み戻せます。

v4.5.5-nikque.12 までの版では、この `.sgf` を `load` すると、同じ警告の後、手が、ふつうの初期局面の上に、石を返さないまま置かれた、おかしな盤になっていました。

### そのほかの形式の例

同じ 5 手の対局（`F5D6C3D3C4`）を保存した例です。

SGF：

```
(;FF[4]GM[2]AP[edax:4.5.5]
PC[Edax]DT[2026-10-07]
PB[?]PW[?]
SZ[8]AB[e4][d5]AW[d4][e5]PL[B]
RE[Void]
B[f5];W[d6];
B[c3];W[d3];
B[c4];)
```

GGF：

```
(;GM[othello]PC[Edax]PB[?]PW[?]RE[-127.000]BO[8 -------- -------- -------- ---O*--- ---*O--- -------- -------- -------- *]B[F5]W[D6]B[C3]W[D3]B[C4];)
```

- SGF では、パスは `B[PA]`・`W[PA]` と書かれます（v4.5.5-nikque.13 から、パスのある SGF を読み戻せます。それより前の版では、読み込みに失敗していました）。
- **打てない手を含む棋譜のファイル**：`.ggf`・`.sgf`・`.pgn`・`.edx` のファイルに、打てない手（石を 1 つも返せない手、石のあるマスへの手）が入っていると、その棋譜は読み込まれません。盤も対局も、`load` の前のままです。どの手が打てなかったかが、`WARNING: Illegal move #2: A1` のように表示されます（`#2` は、0 から数えた手の番号です。`.ggf`・`.sgf`・`.pgn` では、その前に `WARNING: error while importing a GGF game` のような警告も出ます）。`.txt` だけは別で、打てない手の手前までが読み込まれ、`WARNING: game text: "A1F4" is not a move that can be played here: the rest of the line is not read` と表示されます（`book add` で読むときも同じです）。
  - v4.5.5-nikque.12 までの版では、石を 1 つも返せない手が、石を返さないまま盤に置かれて、読み込まれていました（実際にはあり得ない盤になります）。古い版で、読み込みのときに警告が出たら、その盤は使わずに、`init` でやり直してください。`.txt` の行が途中までしか読まれなかったときの警告も、古い版にはありません。
- v4.5.5-nikque.12 までの版では、終局していない対局の `.pgn` を読み込むと、`WARNING: uncomplete game.` と表示されます（読み込みは、できています）。
- PGN の読み込みは、60 手までです。
- 棋譜として保存されるのは、着手 60 個までです。

## 10.2 棋譜の束を扱う：base のコマンド

`base` で始まるコマンドは、棋譜のファイル（たくさんの対局が入ったもの）をまとめて扱います。今の対局や book には関係しません。

| コマンド | 意味 |
|---|---|
| `base convert 入力 出力` | 形式を変える（拡張子で形式が決まる） |
| `base unique 入力 出力` | 同じ対局を 1 つにまとめる |
| `base compare ファイル1 ファイル2` | 2 つのファイルに共通する局面の数を表示する |
| `base check ファイル n` | 各対局の終盤（空きが n 以下の局面から。省くと 24）を完全読みで調べ、悪手のある対局を表示する |
| `base correct ファイル n` | 同じく調べて、悪手を最善の手に直す。**ファイルを書き換える** |
| `base complete ファイル` | 終局まで行っていない対局を、Edax が打ち継いで終局させる。**ファイルを書き換える** |
| `base problem ファイル n 出力` | 各対局の、空きが n の局面を、問題のファイルに書き出す |
| `base tofen ファイル n 出力` | 同じ局面を、FEN という書き方で書き出す |

`base` の後ろの言葉は、大文字で書いても通ります。

例：

```
>base convert games.txt games.sgf
WARNING: Cannot open file games.sgf

>base unique games.txt uniq.txt
WARNING: Cannot open file uniq.txt

>base compare games.txt uniq.txt
games.txt : 24 positions - 0 original positions
uniq.txt : 24 positions - 0 original positions
24 common positions

>base check full.txt 12
F5F4E3F6E6C5C6D6G4D3F3C4E7D7B5E2G5B4F7E8C8D8F8C7B8G6H5A6B6G3A5A4C3D2B7A8A7B3C2D1F2H3H4H6F1B2C1E1G7H8G8H7G1H1A1B1H2G2A2A3
Game #0 contains 3 errors
1/1 100.0 % done.
```

**知っておくこと**

- **出力先のファイルがすでにあると、棋譜は、その後ろに足されます**（上書きではありません）。同じ名前で 2 回行うと、棋譜が 2 倍になります。新しく作り直したいときは、先に、古いファイルを消すか、別の名前にしてください。
- 出力先が新しいファイルのときは、上の例のように `WARNING: Cannot open file …` と表示されます。これは「足す前に、前からあるファイルを読もうとして、なかった」という意味で、**ファイルは作られています**。`base correct`・`base complete` の後にも、同じ表示が出ます。
- `base check`・`base correct` は、1 局ごとに完全読みを行います。n が大きいと、とても時間がかかります。
- `base complete` は、設定の `level` で打ち継ぎます（v4.5.5-nikque.13 から。それより前の版では、直前の探索の深さのままで、読み切ろうとして終わらなかったり、でたらめな手になったりしていました）。探索の表が、1 手ごとに表示されます。
- `base correct`・`base complete` は、ファイルを読み込めたときだけ、書き換えます（読めないファイルは、そのまま残ります）。
- book や `base` のコマンドの実行中は、`stop` で止まりません（[7.5](07-book-learning.md)）。

## 10.3 問題のファイル（OBF）

Edax に「この局面を解け」と渡すためのファイルです（[11 章](11-solve-bench.md)）。拡張子は `.obf` です。1 行が 1 つの局面です。

```
--XXXXX--OOOXX-O-OOOXXOX-OXOXOXXOXXXOXXX--XOXOXX-XXXOOO--OOOOO-- X; G8:+18; H1:+12; H7:+6; A2:+6;
```

- 最初が盤（64 マス。`X`＝黒、`O`＝白、`-`＝空き）、次が手番（`X` か `O`）、その後に `;` です。
- 続く `手:評価値;` は、分かっている答え（その手を打ったときの石差）です。書かなくてもかまいません。書いてあると、Edax は、自分の答えと比べます。
- `%` から行の終わりまでは、説明として読み飛ばされます。

配布物の `problem` フォルダーには、終盤の問題集（`fforum-1-19.obf` など 4 ファイル。フランスのオセロ連盟の会報に載った問題）が入っています。

`base problem` と `book problem`（[8.8](08-book-maintenance.md)）は、この形で局面を取り出します。
