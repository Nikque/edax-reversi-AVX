# 9. 大きな book を扱う

[目次](README.md) ｜ 前：[8. book の保守](08-book-maintenance.md) ｜ 次：[10. 棋譜と問題のファイル](10-files.md)

この修正版は、数千万〜数億局面の book を、1 台の PC で育てて保守できるように作られています。この章は、大きな book を扱うときの、メモリ・ディスク・時間の目安と、設定、注意をまとめます。

数字は、配布物の README に記録されている実測です。**どれも、ある PC・ある book での値で、ほかの環境での見込みではありません。** 測った環境は、とくに断らないかぎり、Ryzen 9 9950X（論理 CPU 32）、Windows、level 18・深さ 40 の book（約 6 億 6 千万局面、ファイル約 29GB）です。

## 9.1 メモリ

| もの | 大きさ |
|---|---|
| book（メモリの中） | 1 局面あたり、Link を含めて約 50 バイト。6 億 5,700 万局面で 30.6GiB |
| book のファイル | 1 局面あたり約 44 バイト（6 億 6,162 万局面で 29.16GB） |
| 探索のハッシュ表 | [5.6](05-search.md)の表。`auto`・32 スレッドで 226MB |
| 同時に行う探索のハッシュ表（`book-expand-tasks`・`book-store-tasks`） | 探索 1 つごとに 1 組。`auto` の 2 スレッドの探索で各 57MB（16 個で約 0.9GB）。1 スレッドの探索は、level 18 以下で各 14MB |
| `book deviate` 系の、局面を選ぶ間だけ | 1 局面あたり 1 バイト（6 億 5,700 万局面で約 0.9GB） |

- 約 29GB の book で、`book deviate2 5 5` の最大メモリは 33.4GB、`book subtree` は 31.8GB でした。この 2 つの値からの目安は、**book のファイルの大きさ＋ 4〜5GB** です。
- **`book load` は、読み込む間だけ、2 冊ぶんのメモリを使います**（読み込みに失敗したとき、今の book を残すためです）。大きな book は、`book load` ではなく、**`book-file` に指定して起動のときに読ませて**ください（起動のときの読み込みと `book merge` には、この余分がありません）。
- メモリが足りなくなったとき：同時に行う探索の用意ができなければ、警告を出して、同時に行う数を減らして続けます（`not enough memory to search the positions at the same time` など）。book に局面を足せなくなったときは、育てるコマンドが止まります。
- 32 ビット版は、約 8,947 万局面以上の book を読めません（エラーを出して、今の book を保ちます）。大きな book には 64 ビット版を使ってください。
- 入れられる局面の数の上限は 4,294,967,295 です。2,147,483,647 局面を超える book は、v4.5.5-nikque.4 より前の版と、元の Edax では読めません。

## 9.2 ディスク

- **保存のたびに、book と同じ大きさの空きが要ります。** Edax は、いったん別の名前で全部を書いてから、元のファイルと入れ替えます（[6.6](06-book-basics.md)）。29GB の book なら、保存の間は 29GB の空きが必要です。
- **途中経過のファイルは、どれも book まるごとの写しです。** `book.dat` のほかに `book.dat.dev2`、`book.dat.store`、`book.dat.mrg`… と増えていくと、それぞれが book と同じ大きさになります。要らなくなったものは、自分で消してください（Edax は消しません）。
- 目安：book のファイルの 3 倍以上の空き（本体＋途中経過 1 つ＋保存中の一時ファイル）。
- 強制的に止めたときに残った一時ファイル（`book.dat.tmp.番号`）は、Windows では、次の保存のときに Edax が消します。
- **Windows では、`book-file` のフォルダーを含めた長さを 240 文字以内にしてください**（[13 章](13-troubleshooting.md)）。
- 保存にかかる時間：約 29GB の book で 18〜28 秒でした（ディスクの速さで変わります）。

## 9.3 時間の例

| 処理 | 時間（約 6 億 6 千万局面の book） | 記録のある版 |
|---|---|---|
| 起動のときの読み込み | 28〜49 秒 | v4.5.5-nikque.3〜12 |
| 保存 | 18〜28 秒 | v4.5.5-nikque.3 |
| negamax 1 回 | 18〜34 秒 | v4.5.5-nikque.10・12 |
| `book deviate2`・`deviate3` の、広げる対象の選択 | 21〜23 秒 | v4.5.5-nikque.3 |
| `book fix` の全体（読み込みから保存まで） | 222〜242 秒 | v4.5.5-nikque.10 |
| `book merge`（649 万局面の book を取り込む。全体） | 218〜224 秒 | v4.5.5-nikque.10 |
| `book merge`（6 億 5,700 万局面どうし。173.6 万局面が増える） | 263 秒、最大メモリ 37.0GiB | v4.5.5-nikque.3 |
| `book depth 39`＋`book subtree`（深さ 40 → 39。読み込みから終わりまで） | 177 秒 | v4.5.5-nikque.12 |

- 測った日・ほかに動いていたプログラムで、同じ処理でも 1〜2 割は変わっています。
- v4.5.5-nikque.2（元の Edax に不具合の修正だけを入れた版）では、同じ book の読み込みに 446 秒、保存に 657 秒、negamax に 937 秒、6 億局面どうしの merge に 4 時間半かかっていました（README の v4.5.5-nikque.3 の節）。

**育てる時間は、ほとんどが探索の時間**です。約 6 億 6 千万局面の book に `book deviate2 5 5` を行うと、1 周の対象（`todo`）が 275 万件ありました。広げる速さは、32 スレッド・`book-expand-tasks = auto` で、毎秒 32〜40 件でした（時間帯で変わります）。この速さが続けば、1 周に約 19〜24 時間、という計算になります（1 周を通して測った値ではありません）。

## 9.4 設定

配布物の `config.ini` は、大きな book を育てることを考えた値になっています。論理 CPU 32 の PC で level 18 の book を育てるときの例です。

```
level = 18
n-tasks = 32
hash-table-size = auto
book-file = data/book.dat
book-expand-tasks = auto
book-store-tasks = auto
book-save-interval = 360
book-deviate-save-rounds = 1
book-merge-auto-save = on
```

| 設定 | 考え方 |
|---|---|
| `n-tasks` | 全部の論理 CPU を使うなら `auto`。**ほかの作業もするなら、減らします**（たとえば半分）。negamax・広げる対象の選択・Link の張り直しも、このスレッドの数で並列に動きます |
| `book-expand-tasks` | `auto`。level 18 以下では「2 スレッドの探索を `n-tasks ÷ 2` 個」、対象の多い周（`n-tasks` の 32 倍以上）は「1 スレッドの探索を `n-tasks` 個」になります。level 19〜24 では 4 スレッドずつ、それより上では 8 スレッドずつです。高い level では、数で指定して速さを比べてください（README は、32 スレッドなら 4 や 8 から、としています） |
| `book-store-tasks` | `auto`（棋譜を `n-tasks` 本ずつ同時に学習） |
| `hash-table-size` | `auto`。大きくしても、短い探索は速くなりません |
| `book-save-interval` | 1 回の保存に約 30 秒かかり、book と同じ大きさのファイルを書くことを考えて決めます。配布物は 360 分（6 時間） |
| `book-deviate-save-rounds` | 1 周が長い（何時間も）なら `1`。1 周が短い（数分）のに毎周 29GB を書くのは無駄なので、そのときは大きくします |

**前の版・元の Edax と同じ動きにする設定**：`book-expand-tasks = 1`、`book-store-tasks = 1`。`auto` でできる book は、`1` でできる book と、一部の Leaf の手・評価値が違います（[7.2](07-book-learning.md)・[7.6](07-book-learning.md)。README に、違った局面の数の実測があります）。

## 9.5 大きな book での手順の注意

1. **保守の前に、ファイルの写しを取る。** `book subtree`・`book prune`・`book merge`・`book correct`・`book leaf-recalculate` は、book を大きく変えます。終了のときの保存は、`book-file` を上書きします（[8.4](08-book-maintenance.md)）。
2. **大きな book を使っている間は、`book new` を打たない。** メモリの中の book が捨てられ、元に戻すには、ファイルを読み直す時間がかかります。そのまま終了すると、`book-file` のファイルは新しい空の book になり、それまでのファイルは `.old` を付けた名前で残ります（v4.5.5-nikque.12 までの版では、残らずに上書きされます。[6.7](06-book-basics.md)）。
3. **`book export`（文字のファイル）は、大きな book ではとても大きなファイルになります。** ふだんの保存や受け渡しには、`book save` のファイルを使ってください。
4. **止めるときは、保存の間隔を思い出す。** 育てるコマンドを止めると、最後の保存の後の分を失います（[7.5](07-book-learning.md)）。`quit` は、コマンドが終わるまで待ちます。
5. **終了の前に、どのファイルが最新かを確かめる。** 育てるコマンドが終わってから `quit` すれば、`book.dat` が最新です。途中で止めたなら、`book.dat.dev2` などのほうが新しいはずです。日時と大きさで確かめてから、名前を付け替えてください。
6. **同じ book のファイルを、2 つの Edax で同時に開いて保存しない。** 後から保存したほうが、先のものを上書きします。並行して育てるなら、別々のファイルにして、後で `book merge` でまとめます。
7. **小さい book で手順を試してから、大きい book で行う。** コマンドの順番・ファイルの名前・保存先を、数秒で終わる book で確かめておくと、失敗が減ります。

## 9.6 book の大きさと深さ・level の関係

- level を上げると、1 局面を足す時間が延びます。README の実測（level 18、約 6 億 6 千万局面の book の `book deviate2 5 5`）では、1 件を広げるのに約 3,300 万ノードの探索でした。
- 深さを 1 つ増やすと、局面の数は大きく増えます。README の例では、同じ book の深さを 40 から 39 に減らすと、6 億 6,162 万局面が 5 億 2,408 万局面になりました（いちばん深い層だけで 1 億 3,754 万局面）。
- `book deviate2 X Y` の数を 1 つ増やすと、対象は何倍にもなります。必ず、小さい数から試してください。
